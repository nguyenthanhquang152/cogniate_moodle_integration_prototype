1. Tenancy: one engine, three LMS types

The LTI service is LMS-neutral. Each LMS gets a fixed provider profile, not new launch code. The tenant key is the tool account, the issuer, the client ID and the deployment ID (ADR-011 §4).

Exclusive (Moodle, Canvas)

One connection owns the platform and all its deployments. A second library needs its own Canvas developer key. Reuse gives PLATFORM_IN_USE.

Shared (Blackboard)

One Blackboard application serves all schools. Each school is one deployment that one connection owns. A disconnect switches off only that deployment.

2. Operator approval grant and its trust boundary

Client IDs and deployment IDs are not secrets. So every new Canvas or Blackboard binding needs a one-time approval from a Cogniate operator (ADR-011 §4a, operator guide).

  1. Cogniate library user
    Makes a new Canvas or Blackboard connection in the portal. It is pending.
  2. LMS admin
    Installs the tool in the LMS and reads the client ID and deployment ID.
  3. LMS admin → operator
    Asks for an approval through an institutional channel, with the library, site, service URL and IDs.
  4. Operator
    Checks that the request comes from the institution. Records an evidence reference.
  5. Operator
    Runs app:grant issue. Reads the printed library and connection names first. Gets a one-time code.
  6. Operator → library user
    Gives the code through a private channel. It works once and expires after 24 hours by default.
  7. Library user
    Enters the IDs and the code, then clicks Save in a session of the same library.
  8. Cogniate app
    Checks the code and the values, activates the record, then commits the approval. Only this approval gives launch and grade authority.

Containment: the operator can suspend, then release a wrong binding without the library's session. Nothing moves to another library. Results per record: fenced, absent, not_owned, deleted, kept_inactive, failed (operator guide §3).

D-12 in plain words. Only self-hosted Canvas is affected; hosted Canvas and Blackboard issuers are reserved. After a release, a Moodle connection of another library can take the freed issuer and client ID first. This can block setup. It gives no Canvas access, because launch check 14 refuses Canvas launches before storage.

Operator order: issue the rightful grant, suspend, release, then redeem at once. Prompt redemption makes the window short, but it cannot close it. An enterprise service needs a reserved-identifier or quarantine design first.
