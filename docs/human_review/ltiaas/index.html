1. What LA is

Milestone LA turns the Cogniate LTI service into an "LTI as a service" product. Each LMS is now one channel: one folder of data and settings. A new LTI LMS needs no change in the core code. LA also adds the controls that a paid service needs: rate limits, tool accounts, an operator API, an audit log, key rotation and backups.

LA keeps Moodle, Canvas and Blackboard as they were, and adds two new channels: a generic LTI 1.3 channel for any LMS of the same kind (for example Sakai or Open edX) and D2L Brightspace.

2. What LA built

Channels

One folder per LMS, found by discovery. Moodle, Canvas and Blackboard moved in with no behaviour change. New: LTI 1.3 (generic) and D2L Brightspace. The D2L channel changed 0 core files.

LTI Advantage

Launches in a frame without third-party cookies (platform storage), launches without a course context, Deep Linking with Cancel and several items, no NRPS scope in any channel, Canvas Dynamic Registration with an approval code, score extras, trusted extra audiences.

Grades and records

Placements and learning records, one send queue with leases, fair waiting when an LMS throttles, an optional separate worker process.

Operations and security

Rate limits, tool accounts (tenants), an operator API with its own keys, an audit log, API key and signing key rotation, key rings for the master keys, service key revoke, safe retries, metrics and readiness checks, strict production start rules.

Onboarding (Could)

A "Check connection" panel (Canvas, LTI 1.3) and a connection health view in the portal. The record of launch refusals (LA-E6-06) is deferred.

Tests and gates

A contract suite (K0), a simulator with six LMS providers, a channel kit (K1), browser checks (K2), lint rules that keep LMS names out of the core, an add-channel gate (F2), a local CI script.

Guides

Operator runbook, admin guides (LTI 1.3, D2L Brightspace, LA changes for Moodle, Canvas and Blackboard), the add-a-channel guide, and the list of spec deviations.

4. Wave-end gate and milestone-end runs

The gate ran the frozen suites on the wave-end build and again on a8bbac53, the SHA of the first final runs. Then two milestone-end full runs (D1 and D2) ran on a8bbac53. All 11 gate checks pass on a8bbac53.

LA-H27 merges the Blackboard and Canvas final result into LA. So the full gate runs again on the new final product SHA 4f10c5fd: pending: re-gate on 4f10c5fd (LD-29). The a8bbac53 results stay true for that SHA. The E0 close-out evidence (LA-E0-02: the legacy baseline and the rate peaks; LA-E0-03: the Moodle golden segment) is in progress (LD-29), on a re-captured baseline.

QA found 13 differences (WE-F1 to WE-F13) and two load flakes. Each one has a recorded decision:

  • 2 product fixes: a higher default rate limit for admin API calls (WE-F1), and a faster stop of open HTTP requests at shutdown (WE-F4).
  • The new behaviour is right, and the frozen test changes: five findings, each test change approved by two reviewers (WE-F2, -F3, -F6, -F7, -F8).
  • A test or harness problem, not an LA difference: WE-F5, -F9, -F10, -F11, -F13.
  • Two load flakes in run D2 (T7 under two Moodle stacks, one M2 keyboard case): each rerun passed. A flaky run never counts as PASS.
  • One flake stays open: WE-F12. One grade test fails sometimes, on the intake build too. Test hardening comes after LA.
  • One kit defect is being fixed: F-LA-E7-06-WALK-02, a false FAIL in the kit when a new channel is added (LD-30). It is not a product defect.

5. What is not proven

  • No real Canvas, Blackboard, D2L Brightspace or other LTI 1.3 site took part. Every result for these LMSs is a simulator result. Their menu names and some field names come from vendor documentation. A live proof on an open-source LMS is decision LA-H26 (after LA).
  • The re-gate on the new final product SHA 4f10c5fd: pending: re-gate on 4f10c5fd (LD-29). Every suite of the milestone-end double run and the kit K1 runs again on it. Until then, the gate results are results on a8bbac53 only.
  • Known limit (BD-A1-121): a Dynamic Registration of a desire2learn site on a Moodle or LTI 1.3 connection is refused with the page REGISTRATION_FAILED, not with the page that names D2L Brightspace. Nothing is sent and nothing is stored. The fix is in LG (spec-deviations §7).
  • Canvas Dynamic Registration for Instructure-hosted Canvas: refused on purpose until a live Canvas check. Hosted Canvas uses the developer key.
  • A production host: the strict production start rules exist and pass their tests, but the LA Docker stack cannot run in production mode. A production host setup is milestone LG.
  • Load, scale, high availability and 1EdTech certification: not in LA (certification shape: LA-H9).
  • Not built: the tenant reads GET /api/audit and GET /api/account (Should; no task had them); ungraded items (LA-H22); a claim policy per tool account (LA-H4); the verified admin launch (LA-H24); the record of launch refusals (LA-E6-06, deferred); the app-edge limit on the handoff pages (LA-E4-06) and other browser checks (LA-E7-12), both cut to LG (LD-28).
