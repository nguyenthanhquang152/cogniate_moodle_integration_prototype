These decisions belong to people, not to the team of agents. Each has our recommendation. The prototype uses the recommendation until a human decides. The Lead moves the open items to `docs/human_review/decisions-needed.md`.

"Blocks" = what waits for the answer.

| Q18 | Product + Engineering | Moodle in a subfolder (wwwroot with a path, for example `https://school.edu/moodle`). Moodle 5.2.4 sets the issuer to `$CFG->wwwroot` (`mod/lti/openid-configuration.php` line 39), so it has the path. Today: (a) dynamic registration is refused with `ISSUER_MISMATCH`, because security §2.4 requires issuer = origin of the configuration URL; (b) `siteUrl` must be an https origin, so web service calls and course links (T8) go to the wrong path; (c) manual connect compares only the issuer **origin** with `siteUrl`, so it may work, but nobody tested it. MoodleCloud is not affected (its sites are at the host root). Our local stack has Moodle at the root only, so we cannot test a fix before the hand-over (conformance F5, MAJOR, accepted limitation). | Support it before the first self-hosted customer. Design: (1) `siteUrl` = the Moodle base URL: https, an optional path without a trailing `/`, no query or fragment. (2) The issuer must equal the base URL exactly, and is stored and compared exactly as given (launch check 5 already compares exactly). (3) The configuration URL must have the issuer origin, and its path must start with the issuer path + `/` (an issuer with no path keeps today's rule). (4) Every endpoint (auth, token, JWKS, registration, deep-link return) stays on the issuer origin; CSP `{issuer}` stays an origin. (5) Web service and course URLs are built from the base URL. Size: about 1 day. Changes: security §2.4; LTI contract §2.4; app contract §4 (`siteUrl`, PUT platform, `SITE_MISMATCH`) and §11; `lti/registration.ts`, `app/connections.ts`, `tool-pages` register check, `clients/moodle-ws.ts`, `app/publications.ts`; new ACs for the subfolder rules (registration, manual connect, launch, grades); AC-T4-09 (`SITE_MISMATCH`), AC-T8-08 and AC-T8-09 (web services) change; a stack variant with Moodle at `/moodle` for the tests. | Product + Engineering | Self-hosted Moodle customers in a subfolder |


Q4 remains a product decision. Its best-result recommendation describes the intended grade policy, not a proven guarantee of remote write order. The [ADR-010 bounded confirmation policy](adr/ADR-010-grade-and-completion-policy.md#p2-bounded-confirmation-after-uncertain-delivery-2026-10-19) records the P2 limit: an older timed-out Moodle request can write after an accepted confirmation. This note does not close Q4 or add a human approval of that limit.

## Residual risks (accepted for the prototype)

The Docs role copies this list into `docs/human_review/`. Each item was judged by a reviewer and accepted by the Lead. A human confirms before production.

| # | Risk | Why accepted | Where |
| --- | --- | --- | --- |
| R1 | A "new" dynamic registration that returns the client id of an existing platform with no connection binds that platform to the new connection. | A standard Moodle cannot cause it (new client id per registration; a reused token gives `token_already_used`). Only a site admin with a modified Moodle could. | security §2.6 (T4b1, Reviewer-A) |
| R2 | A person can send someone an unused `/tool/launch?ltik=` URL; the first person to open it gets the attempt (session fixation before first use). | Needs social engineering; the only gain is credit for the victim's work. Part of the ltik-in-URL model. | security §4 (T0 round 2, Reviewer-A) |
| R3 | Scores are computed in the browser and can be forged with developer tools. | Accepted for completion-type courses only (Q8). | security §7 |
| R4 | Teacher Deep Linking can fail in Safari (state cookie in Moodle's iframe). | Moodle 5.2 has no LTI client-side storage; Chromium and Firefox work (Q16). | security §3 |
| R5 | All libraries share one content origin, so one library's package code shares browser storage with another library's packages. | Prototype only; no cookies on the content origin, and the proxy drops `Cookie`. Production needs one content subdomain per tenant (Q10). | security §7 (T5b) |
