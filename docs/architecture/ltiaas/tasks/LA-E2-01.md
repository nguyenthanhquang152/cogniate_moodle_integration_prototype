## Goal

The LTI service gets the E2 profile traits as data and applies them without a profile-id branch: `issuerKind`, `endpointOrigins`, `clientAssertionAud`, `assertionDeploymentId` and `dynamicRegistration`. An active admin-value platform keeps every endpoint and the assertion audience on the issuer origin (I-SELF); values off that origin are allowed only in a staged, inactive create. Endpoint hosts that are fixed or issuer hosts of any loaded profile are refused.

## Scope

- In: D2 trait table for every baseline profile; load check 7 for `issuerKind` against `issuer`; `{platformValue}` (stored `clientAssertionAud`, else the token URL) and the `array` form; the optional `deployment_id` assertion claim (default off); token requests ask only for granted scopes when `granted_scopes` is set; the trait fields on `GET /api/providers`; the active and staged create rules of A2 delta §4.6.1 rule 7; the refused-host rule.
- Out: the DR fixes (LA-E2-02); the `lti-generic` and `brightspace` folders (K); the app side (LA-E2-03, LA-E2-04).

## Design notes

- Trait fields (A1 BD-A1-74; LA-ADR-02 D2 note): the five E2 traits are optional in the kernel `ProfileSource` type (one RQ-2 commit for `packages/channel-kernel/src/profiles.ts`), the registry fills the strictest default, the three baseline files set every value, and load check 7 refuses a value that disagrees with the profile.
- `clientAssertionAudArray` (A1 BD-A1-75): stays as a legacy field in this task; load check 7 refuses a `clientAssertionAud.form` that disagrees with it; the default form comes from it; the token client reads only `clientAssertionAud`. LA-E2-02 removes it.
- The end-to-end K1 cases with an `any-https` profile run in LA-E2-03 (when `lti-generic` exists). This task proves the rules with test profiles in unit tests and keeps every baseline answer equal.
