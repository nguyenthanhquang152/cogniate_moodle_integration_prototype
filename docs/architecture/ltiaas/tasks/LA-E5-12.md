## Goal

The app operator commands `app:grant` and `app:binding` name their operator and record the grant evidence. Each run writes one app audit event in the same transaction as its local change. The M1 commands work unchanged in the `default` and `acceptance` profiles.

## Scope

In:
- New flags `--operator <name>`, `--evidence-channel`, `--evidence-ref` on `app:grant issue`, `app:binding suspend` and `app:binding release` (LA-ADR-07 D5); `--operator` on `app:grant revoke`.
- The policy decision of LA-E5-11 before any change; a refusal prints one line, exits 1, and stores nothing (no grant row, no audit event).
- One app audit event per run (actions `grant.issue`, `grant.revoke`, `binding.suspend`, `binding.release`), in the same transaction as the local change; a refused run on a known grant or connection writes one event with `result: refused`.
- `note_present` in the event; the note text stays where M1 keeps it (`binding_grant.note`; suspend and release log only `note_present`).

Out:
- The writer, the policy and `app:audit list` (LA-E5-11).
- The grant bound-value flags (`--issuer` …, `--accept-staged`, `--confirm-foreign-hosts`): A1's LA-E2-04, also lane K.

## Design notes

- FYI (A1 BD-A1-48; data-model §5): each `app:grant` and `app:binding` event sets `connection_id` (the target stays the grant or binding), so `app:audit list --connection <id>` finds it (AC-06).
- Operator policy seam (BD-A2-45): `evaluateOperatorPolicy(input, env = process.env)` gives `{ allowed: true, actor: { type: 'operator', id }, details: { evidence_channel?, evidence_ref?, note_present } }` or `{ allowed: false, message }`. A refusal writes no audit event and no row, prints the one line, exits 1, and logs `operator_refused {reason}`. `OPERATORS` and `OPERATORS_FILE` both set: refuse (`operators_ambiguous`). Every grant and binding event sets `connectionId`.
- Order (README §6a): K's S5 change of these files lands first; then this task.
- QA runs the production rule per process with `docker compose exec -e STACK_PROFILE=production -e OPERATORS=qa-op cogniate-app npm run app:grant -- issue …` (tasks README §2 allowance, README OC-7). The service itself stays in the `acceptance` profile.
