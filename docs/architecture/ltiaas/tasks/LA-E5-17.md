## Goal

Operators can see the health of the LTI service. The operator listener serves OpenMetrics text at `/metrics`. Both listeners serve `/readyz`. In the `production` profile `/healthz` shows only status and service, and `http_request` lines carry the tenant id.

| new `services/lti-service/src/http/metrics.ts` | `services/lti-service/src/lti/login.ts`, `lti/launch.ts` (L2 in B3; protocol log fields are LA-E5-18) |
| `services/lti-service/src/http/app.ts` | `services/lti-service/src/http/routes/**` (other lanes) |

Needs from other lanes: none. Counters for launches and outbound calls are read through hooks or the logger, not by edits in L files. If a counter needs a call in an L file, L adds one line on request (through the Lead).

## Scope

- In: `GET /metrics` on the operator listener with the metrics of operability §4.2 that exist at build time; `/readyz` on both listeners (checks: `SELECT 1`, every migration applied, `keyProvider.ready()`); `reasons` only on the operator listener; production `/healthz`; `tool_account_id` in `http_request` when the path names an account.
- Out: app metrics (A1, [app API delta §8a](../contracts/cogniate-app-api-delta.md#8a-app-metrics-should-with-e5-metrics)); the alert rules themselves (a collector config, LG); protocol log fields (LA-E5-18).

## Design notes

- Raw transactions (BD-A2-74; Reviewer-A A-LA-E5-17-03): when `db.isTransaction` is true and no helper scope is open, `afterCommit()` and the nested `transaction()` path throw a `TypeError`; remove both "run now" branches for that case. Tests: a raw `BEGIN IMMEDIATE`, then an audit insert, then `ROLLBACK` throws and leaves the counter unchanged; a raw `BEGIN`, then `transaction()`, throws at entry; `afterCommit` in autocommit runs at once; the existing helper paths stay green. Optional Should (lane P): an F5 rule against raw transaction statements outside `migrations.ts`.
- Fix round (BD-A2-60, BD-A2-61; review A-/B-LA-E5-17-01, A-LA-E5-17-02): (1) `afterCommit(db, fn)` in `packages/shared/src/migrations.ts` (S1, by RQ-2), with per-scope buffers (merge at `RELEASE`, drop at `ROLLBACK TO` and `ROLLBACK`, run once after the outermost `COMMIT`, at once in autocommit); `insertAuditEvent` registers the counter callback at every insert; the BD-A2-52 exception goes; tests: a nested change in a committed outer transaction counts, an outer rollback counts nothing, the real `key-rewrap` completion counts once, and `metrics.test.ts:165-173` is inverted. (2) `http_request.path` = `req.routeOptions.url`, or `<unmatched>`; tests with an unknown account and an encoded personal value (for example `/lti/login/alice@example.test` logs `/lti/login/:account`). `redactPath` stays in `packages/shared` (the app still uses it).
- Sources (BD-A2-52; operability §4.2 "Sources"): a limiter observer before sampling; audit counts after the outermost commit only; RQ-1 to L for injected `onTokenResult({platformId, ok})` (token client) and `onJwksFetch({platformId, ok, fetchedAt})` (JWKS cache), no-op by default; JWKS attribution (BD-A2-54): `verify(token, jwksUrl, traceId, platformId?)`; one `onJwksFetch` event per verify call that waited on a fetch (starter or single-flight joiner), with its own platform id; none for a cache hit or no platform id; plus a read-only cache getter `lastSuccessAt(jwksUrl): number | null`, from which the metrics module computes the age per stored platform at scrape time; logs, the HTTP hook and store queries for the rest. A series with no accurate source is not exposed (no zero). `tool_account_id` only for a stored account id (empty otherwise); `platform_id` only a stored id. Unit tests: a rolled-back audit insert does not count; a sampled-away refusal still counts.
- Label rules (LA-ADR-06 D10): no personal data; `platform_id` only on the JWKS and token failure counters; `tool_account_id` is bounded by the account count.
- `/metrics` has no route through the proxy, because the operator listener has none (LA-ADR-06 D3).
