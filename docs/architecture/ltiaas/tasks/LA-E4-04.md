## Goal

Write the progress record kinds for later reporters (xAPI in LC) and keep the start and submit times of an attempt on its records. The `lti-ags` reporter ignores the progress kinds, so grade return does not change (ADR-010 rule 2).

## Files

| May edit | Must not edit |
| --- | --- |
| `services/cogniate-app/src/kernel/records/**`, `domain/attempts.ts`, `drivers/lti-ags/**` | K and L files; no new migration (the `014` columns exist) |

## Scope

- In: one `started` record at the first commit of an attempt; one `progressed` record when the stored progress changes; one `submitted` record when the attempt reaches a final outcome; `started_at` and `submitted_at` on every record of the attempt; the AGS submission fields come from these times when A2's LA-E3-11 sends them.
- Out: any new reporter; record retention (LA-H4).

## Design notes

- Legacy submission time (A1 BD-A1-66; Reviewer-B B-LA-E4-04-01; LA-ADR-03 D3 "Legacy times"): a final attempt with no `submitted` and no `final` record takes its `updated_at` as stored before the commit (read before the commit changes the row), and the commit writes one `submitted` record with that `occurred_at`; later commits find the same time.
- AGS submission times (A1 BD-A1-60): this task stores `started_at` and `submitted_at` on the learning records only; the `lti-ags` score body stays the LA-ADR-03 D5 body (AC-04: no visible change), although A2's LA-E3-11 now lets the LTI service forward `submission`. Mapping the times into the score body changes every score POST, so it needs its own LA-IC, a G2/G3 score-body golden update and an LD-9 list (lead QA), in a later lane R task that the Lead schedules.
- "Progress changes" uses the tracking state that the commit stores today; the exact trigger is an Author choice, recorded in the task's unit tests. QA checks only counts and the no-dispatch rule.
