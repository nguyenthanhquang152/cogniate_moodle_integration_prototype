## Goal

The app job runner can run in the web process (default, as today) or alone with `npm run worker` (the same code). When the worker runs, the web process has `APP_JOB_RUNNER=off`. The `production` profile refuses a start that would run two runners with one instance id.

## Scope

- In: `APP_JOB_RUNNER` (`on` default, `off`); the `worker` entry; the `production` refusal; distinct instance ids for two processes.
- Out: a production topology (A2 operability); compose services for a worker (not in LA).

## Design notes

- The check uses the heartbeat table: each `job_instance` row stores the process role (`web` or `worker`; data-model §3 "Worker check"). In the `production` profile, a runner start with a live row of the other role exits with `config_refused {reason: "job_runner_twice"}`; other profiles log `job_runner_twice` at warn level.
