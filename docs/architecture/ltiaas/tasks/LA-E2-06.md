## Goal

D2L administrators can start a Dynamic Registration. Because the D2L token host is off the issuer origin, every `brightspace` DR with the real D2L endpoints is staged: the LTI service creates an inactive platform, and an operator grant with `--accept-staged` and `--confirm-foreign-hosts` activates it. The change is data in the channel folder only.

## Design notes

- Staged by I-SELF, not by policy (A1 BD-A1-108; Codex Reviewer-A question at `326ceae`): `brightspace` DR follows the generic D5 item 10 rule. A configuration with the real D2L shape (token host `auth.brightspace.com`, audience off the issuer origin) breaks I-SELF and is staged (AC-02). A configuration with every endpoint on the issuer origin completes active with `self`, as for `lti-generic`; this is correct, not a defect. No code change. Optional wording fix for K in a later commit: the comments in `packages/channels/brightspace/lti-profiles.ts:3` and the test title in `packages/channels/brightspace/channel.test.ts:41` say "always staged"; "staged by I-SELF (every real D2L configuration)" is exact. An optional UNIT test may pin the same-origin control (active, `self`).
