## Goal

A library user can test a connection from the portal. The app asks the LTI service to fetch the platform JWKS and to request one access token with our client assertion. The answer says what works and what fails, with a clear text, and reads no course or user data.

## Scope

- In: LTI route (Bearer, `admin` scope; JWKS fetch and one token request through the guarded client; answer of contract delta §2.6; log `platform_check`); app route (guard `setup.connectionCheck`; answer `{ result, checkedAt, details }`; one check per connection per minute; log `connection_check`); portal button and the three texts of LA-ADR-08 D4.
- Out: storing the last result for the health view (LA-E6-02 writes a `check` row into `connection_event`; until then the result is only returned).

## Design notes

- Log and audit names (BD-A2-99): `token_result` in `platform_check` (LTI) and `connection_check` (app), `tokenResult` in the `platform.check` audit details, each with the value `{ ok, scope?, detail? }`; `jwks` keeps its name; the HTTP answers keep `token`. The shared redaction rule does not change. Unit test: a logged `connection_check` line shows `token_result.ok`, not `[redacted]`.
- Local choices (BD-A2-98; LA-ADR-08 D4 "Work" and "Portal"; contract delta §2.6): (a) changed: no granted AGS scope gives `token.detail: no_granted_scope` and no token request, with the portal text "{LMS} gave Cogniate no grade scope. Allow the grade (AGS) scopes for the Cogniate tool in {LMS}."; (b) `jwks.detail: invalid_jwks`, `http_<status>` or the outbound reason; (c) changed for one case: an unknown `deploymentId` gives `404 UNKNOWN_DEPLOYMENT` (no `deploymentId` = the first active deployment; a known inactive one = `403 DEPLOYMENT_NOT_ACTIVE`); (d) one "Check connection" panel on the connection page only; (e) another token failure: "{LMS} did not give Cogniate an access token." with the code. Staged records: `409 CONNECTION_NOT_READY` (app) and `403 PLATFORM_NOT_ACTIVE` (LTI) before any call.
- The LTI route runs only for an **active** platform and deployment: else `403 PLATFORM_NOT_ACTIVE` or `403 DEPLOYMENT_NOT_ACTIVE` (base codes). So a client assertion goes only to a token endpoint that the binding proved (LA-ADR-07 rule A6, A-LAD-01).
- The token request uses one granted AGS scope (`lineitem.readonly` when granted, else `score`). The token is not cached and not returned.
