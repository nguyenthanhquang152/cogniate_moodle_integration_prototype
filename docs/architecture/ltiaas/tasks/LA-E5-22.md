## Goal

The Cogniate app seals its stored secrets with the same versioned key provider as the LTI service. Each sealed value gets associated data that binds it to its row, and the master key can rotate with a re-wrap. Existing blobs keep opening, and the runtime token keeps its value.

## Scope

- In: one `seal`/`open` wrapper with associated data `app:<table>:<column>:<library_id>:<row key>`; legacy blobs open; new blobs use the active version; the runtime token uses `mac` with the `legacy` version, so its value does not change; `APP_MASTER_KEY_FILE`; re-wrap of app blobs on demand (the app runner, R).
- Out: the LTI service (LA-E5-08, LA-E5-09); a cloud KMS adapter (LG).

## Design notes

- Missing key version (BD-A2-97; Reviewer-A A-LA-E5-22-02): a version not in the bound ring (`key_provider_not_bound`, or `key_open_failed` with the header version missing) maps to `retryable` (not uncertain) for a score dispatch, and to a degraded row (`registrationUrl: null`, `registrationUrlExpiresAt: null`, answer `200`) for the connection list and detail. An authentication failure stays `local_failure` or `500`. No new error code. `app:keys rewrap` output and help say: "write the ring, restart the app and check /readyz = 200, then rewrap".
- Design points (BD-A2-91; LA-ADR-06 D6 "Scope in LA", D12; operability §2, §6.3): points 2–4 ratified as K wrote them (AAD rows, ref token by `ref_token_hash`, runtime token byte-identical; bound `masterKey` handles; `app:keys status|rewrap` with the operator policy `evidenceRequired: false`, authenticated metadata, compare-and-set batches, one audit event). Point 1 changed: (a) `APP_KEYRING_FILE` default `/run/secrets/app-keys/keyring.json`, host folder `infra/.secrets/app-keys/` (`0700`), hidden from `e2e` by its own tmpfs with a check in `compose-e2e-secrets.test.mjs`, made by `stack-up.sh` and `prepare_e2e` (the compose, stack and test lines go to their owners); (b) `production` refuses `APP_MASTER_KEY` as an environment value (`app_master_key_in_env`). Unit tests: a ring without `legacy` stops the start; `APP_MASTER_KEY` in the production environment is refused; a re-wrap of a colliding legacy blob re-seals it.
- App master key file (A1 BD-A1-72; A2 BD-A2-77..80): `APP_MASTER_KEY_FILE` uses the same shared secret-file reader rules as the LTI service: the file has no group or world permission bit, the check is `fstat` on the opened descriptor, the `production` profile refuses a file that breaks a rule, and a hex key compares case-insensitively.
- Picker ltiks and runtime tokens live hours or less; their rows may keep the legacy form until they expire. The re-wrap covers the long-lived blobs: the web-services token, the ref copy and the resource-link service keys.
