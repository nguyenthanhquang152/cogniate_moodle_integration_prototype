## Goal

Build the LMS-name lint F1 with its per-file ratchet, the add-channel gate F2 and a rule runner for the frozen-data rules F5 that finds its rule files by folder discovery, with the first F5 rule (SQL portability for new SQL files). F1 and F5 run inside `npm run check`; F2 runs on demand. Each tool has a check-one-text mode for QA probes.

## Design notes

- Mechanism: a Node script with the TypeScript compiler API (already a root dev dependency), so the ratchet and the non-TS files fit one tool.
- A rule starts with the task that makes it true, because that task adds the rule file (LA-ADR-04 D1). The runner needs no edit for a new rule.
- Rule module interface (BD-A1-02): the module shape, `check({ path, text })`, discovery, file set, output and exit codes of [README §4 "F5 rule modules"](../README.md#4-rules-that-keep-core-channel-neutral). `rules/audit-event-delete.mjs` (S1) already has this shape: the runner runs it with no edit of that file, and AC-LA-E5-02-10 (pending on this task) closes with it. The runner's file set includes every file that S1's interim test `infra/scripts/fitness-audit-event-delete.test.mjs` walks (`services/`, `packages/`, `apps/`), so that test can later lose its tree walk with no loss. Put the runner's tests in `infra/scripts/fitness/*.test.mjs`, never in `rules/`.
- The SQL portability rule checks only new migration files: files that are not on the integration branch at its landing SHA (applied migrations are history, ADR-006). The rule keeps the exact list of migration file names (per service) on the integration branch at its landing SHA, and checks every other migration file. It does not use a number threshold, because migration numbers can land out of order (data-model §1, BD-A1-04). The rule list (statements that a later Postgres move cannot run as written) is in the script; qa.md copies it.
- Lanes lower their own counts in `f1-baseline.json` by RQ-3.
- BD-A1-07: the F1 fixed list holds the vendor words and the planned channel id `lti-generic`, so AC-03 needs no scratch folder; when LA-E2-03 adds the folder, discovery gives the same word. F2 classes every tracked `infra/**` path as core, with no generated-path exemption: the host manifest wiring (LA-E7-03) writes only git-ignored files (README §4 scope table).
