## Goal

QA proves black-box that the routes that LA adds keep the tenancy rule: library A cannot read or change library B's data, and tool account A cannot read or change account B's data. Each Author task keeps its own port-level two-tenant unit fixtures; this task checks the routes together once they exist.

## Files

| May edit (exclusive) | Must not edit |
| --- | --- |
| `tests/ltiaas/**` (QA area) | every product file; `tests/e2e/**` (QA-E2E) |

Needs from other lanes: none. Fixtures: two libraries with one connection each, and the tool accounts `cogniate` and `qa-second` (M1 fixtures).

## Scope

In:
- AP-07-01: each new app route of LA (app API delta §3, §5; the picker cancel `POST /tool/picker/{pickerId}/cancel` of LA-E3-05; the LA-ADR-08 routes when LA-E6 tasks are built) called in library A's session (or with A's picker) with an id of library B.
- AP-07-02: each new LTI service route that reads or changes tenant data: `/lti/launch/:account/storage-check` (LA-E3-02); `/api/service-keys/revoke`, `/api/audit`, `/api/account` when LA-E5-15 is built; `GET /operator/v1/audit?toolAccountId=` is proven in LA-E5-02 AC-06 (not repeated here, B-LAB-06).
- The frozen isolation ACs stay green: AC-T2-18, AC-T4-16, AC-T4-29, AC-T4-34, AC-T7-08, AC-T7-09.

Out:
- Port-level two-tenant unit fixtures (each Author task, LA-ADR-07 D1; Reviewer-B checks one case per port and per new table).
- Routes of Should and Could tasks that the Lead cuts: their cases are N/A, and qa.md names them.

## Design notes

- Pass rule per case (LA-ADR-07 D1): not found (`404`, or `401`/`403` on the LTI service API), no changed row as seen through the public API, and no outbound call (no `outbound_request` event, zero sink hits).
