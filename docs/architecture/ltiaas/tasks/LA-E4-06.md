## Goal

Limit random-ltik abuse at the app edge without refusing a real class start. A token bucket per client address (600 per minute, burst 200, the LTI `protocol` class values) runs first on `GET /tool/launch` and `GET /tool/deep-link`, before the `handoff` row and before any LTI service call.

## Scope

- In: the bucket, the key (the address that the trusted proxy forwards; IPv6 by its /64), the order rule, the `429` page `RATE_LIMITED` with `Retry-After`, the log line at most once per minute per address.
- Out: the LTI service limits (A2 LA-E5-03); the 60 s providers cache (Could, not built).

None beyond app API delta §5a.

## Acceptance criteria

| AC | Observable outcome | Evidence |
| --- | --- | --- |
| AC-LA-E4-06-01 | Bucket rule: 600 per minute and burst 200 per key; two IPv6 addresses in one /64 share a key; a forwarded address from a sender that is not the trusted proxy is not used as the key. | UNIT |

| AC-LA-E4-06-03 | 400 random ltiks from one address within 10 s: after the bucket is empty the answers are the `429` page with code `RATE_LIMITED` and a `Retry-After` header, and at most 300 requests pass the bucket. | K1-SIM |
| AC-LA-E4-06-04 | After `Retry-After` has passed, a valid launch from the same address works. | K1-SIM |

| AC-LA-E4-06-06 | `GET /tool/deep-link` uses the same bucket: one refused probe after the bucket of AC-03 is empty gives the same `429` page. | K1-SIM |
