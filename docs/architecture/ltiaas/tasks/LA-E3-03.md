## Goal

A valid resource link launch without a `context` claim opens the player. The LTI service also issues a service key for such a launch, scoped with context id `""`. The placement key uses context id `""`. A launch without `sub` is still refused.

## Scope

In:
- LTI service: `serviceKeyForLaunch` issues a key when the launch has an AGS or NRPS claim and a resource link, also without a context (scope: platform, deployment, `""`, resource link id). `GET /api/idtoken` keeps `launch.context` absent.
- App `/tool/launch`: a `LtiResourceLinkRequest` without `context` passes when it has a resource link, a known connection and a publication in the signed target; it passes context id `""` to the placement upsert.

Out: the placement table (R); the results text (R); `/tool/deep-link` (already works without a context).

## Design notes

- The reject rule today is `services/cogniate-app/src/tool-pages/launch.ts:149` (`!context` gives `not_resource_link`). Only the `!context` part goes; the message type and resource link parts stay.
- The service key value for a scope is derived as today; context `""` is part of the input. A repeat launch of the same activity gives the same key.
- LA-IC-05 ships here. QA makes its reviewed test-change list at this task (plan LD-9). QA found no frozen test that expects the old refusal (TEST-STRATEGY §4.7).
