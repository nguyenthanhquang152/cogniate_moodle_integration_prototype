## Goal

The LTI protocol paths use the modules that lane S delivers: the account resolver for every protocol URL, the account status for the login, launch, registration and key pages, and the registration session cap. After this task, no protocol code builds an `/lti/…` URL by hand.

## Scope

In:
- Resolver calls: the login target check (`lti/target.ts`), the Dynamic Registration request (`lti/registration.ts:121-123`), the launch redirect URI and the tool JWKS URL use `protocolUrls(account)` (LA-ADR-06 D2).
- Status gates (contract delta §1.5):
  - `suspended`: login, launch and registration start give the `403` page `TOOL_ACCOUNT_SUSPENDED` and write no state row; `GET /lti/keys/:account` is still served.
  - `closed`: login, launch and registration start give the `404` page `UNKNOWN_TOOL_ACCOUNT`; `GET /lti/keys/:account` gives `404`.
- Session cap at `GET /lti/register/:account`: the session-cap function of LA-E5-03 per (client address, tool account); above the cap, the `409` page `REGISTRATION_SESSION_LIMIT` and no outbound fetch (LA-ADR-06 D1).
- Page codes `TOOL_ACCOUNT_SUSPENDED` (`403`) and `REGISTRATION_SESSION_LIMIT` (`409`) and their action lines in `lti/codes.ts` (contract delta §1.3).
- Fitness rule F5 starts here: no literal `'/lti/launch/'` in product code outside the account resolver.

Out:
- The resolver module and the account columns (LA-E5-04). The buckets (LA-E5-03); the page code `RATE_LIMITED` (L lands it for LA-E5-03 by RQ-1).
- The status gate of the storage-check route: LA-E3-02 adds it when it adds the route (same lane L).
- Host mode (LG).

## Design notes

- Protocol URLs (BD-A2-48, BD-A2-49): the callers in `lti/checks.ts`, `lti/deep-linking.ts`, `lti/launch.ts`, `lti/registration.ts` and their route and test callers take the `protocolUrls(account)` object of the resolver, computed once per request from the loaded account. The `lti/target.ts` helpers take `{ launch, login }`; their string building goes. The storage-check URL is `launch + '/storage-check'`; `jwks_uri` is `keys`. The F5 rule `protocol-urls` (new `infra/scripts/fitness/rules/protocol-urls.mjs`, your process grant) covers the LTI service only: no protocol URL built from an account value outside `accounts/resolver.ts`; route patterns with `/:account` pass; tests are out of scope.
- Behaviour stays the same for an `active` account: the resolver gives today's URLs in path mode (AC-LA-E5-04-10).
- The status gate runs before any state row, outbound fetch or claim storage.
