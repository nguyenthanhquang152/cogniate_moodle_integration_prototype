## Goal

The app exposes `GET /metrics` (OpenMetrics text) and `GET /readyz` on an operator listener that the proxy does not route, so the runbook signals of A2's operability file have data. Values never hold session or tenant data.

## Scope

- In: the listener (`OPERATOR_HOST` default `127.0.0.1`, `OPERATOR_PORT` default `4210`; the `acceptance` compose binds it on the stack network), the metrics of app API delta §8a, `/readyz`.
- Out: LTI service metrics (A2 LA-E5-17); alerts (runbook text, E8).

## Design notes

App API delta §8a has the full rules. Lane R's design calls D1–D4 (A2 BD-A2-88, recorded by A1 BD-A1-100):

- D1 listener: `OPERATOR_HOST` (default `127.0.0.1`) and `OPERATOR_PORT` (default `4210`), the same names and rule as the LTI service. `production` refuses a non-loopback bind at start (`config_refused`, reason `operator_bind_not_loopback`, the LTI service's fixed message).
- D2 sources: the dispatch gauges are store queries at scrape time (no pending row = age `0`). `app_dispatch_sends_total` counts at the commit of the recording transaction (`afterCommit`). `app_grant_redemptions_total` is a scrape-time count of ended `binding_attempt` rows (a true counter only while no job deletes them). `app_grant_compensation_failures_total` and the job series come from log events. `app_launch_refusals_total` gets one line in `tool-pages/launch.ts`. Label guards: an unknown channel id becomes `''`; a reason outside `[a-z][a-z0-9_]{0,63}` becomes `other`.
- D3 readiness (changed by A2): `/readyz` checks only the app: database, migrations, and the key provider when LA-E5-22 lands. No LTI service check.
- D4 topology: the listener runs in the web process only; the send and job series exist only with `APP_JOB_RUNNER=on` and are absent (not zero) with a standalone worker. `JobStale` watches the interval jobs only; `DispatchBacklog` watches the outbox.
