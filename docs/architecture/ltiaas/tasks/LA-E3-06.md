## Goal

The Cogniate channels stop asking for the NRPS scope, but the service keeps the NRPS endpoint. This task adds the optional field `scopes` to `POST /api/registrations/:id/complete`; the service sends it as the registration request `scope`. The task also writes one audit event for each `complete` call. LA-E3-07 makes the channels send the four AGS scopes.

## Scope

In:
- `complete.scopes`: a non-empty subset of the five scopes of ADR-009, sent as the registration request `scope`, space-separated, in the order of the request. Absent = the five scopes (today).
- A scope outside the five, or a scope that the platform does not list in `scopes_supported`, gives `400 INVALID_REQUEST` (field `scopes`) before anything is sent.
- One audit event per authenticated `complete` call: action `registration.complete`, target `registration`, `result ok`, or `refused` with the code of a `4xx` answer (LA-ADR-06 D4 rule 1).

Out: the channel values, the Canvas JSON, Moodle row 13 and the app request (LA-E3-07); `complete.profile`, `bindingRef` and the staged registration (A1's E2-K tasks, same files later in B3, same lane).

## Design notes

- Existing installations need no action. A launch may still carry an NRPS claim; the service still stores it in the service key, and `GET /api/memberships` still answers (LA-ADR-05 D4 item 5).
