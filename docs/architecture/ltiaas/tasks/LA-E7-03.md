## Goal

Make the infra read the simulator hosts from QA-E2E's host manifest `tests/sim/hosts.json`, so that adding a simulator LMS needs no edit of `infra/compose.yaml`, `infra/scripts/lib.sh` or `tests/sim/server.mjs` (today 4 extra edits, R5 §2.4). The manifest is a `tests/**` file, so F2 classes its entries as `sim` and QA-E2E never edits `infra/**` (charter-LA §1).

## Files

| May edit | Must not edit |
| --- | --- |
| `infra/compose.yaml` (the `lms-sim` aliases and the `acceptance` allowlist from the host manifest), `infra/scripts/lib.sh` (certificate SANs from the host manifest; it writes a compose override that is not checked in) | `tests/sim/**` (QA-E2E); `packages/channel-kernel/fitness-scope.json` (K); product source |

## Scope

- In: one read point per consumer (compose aliases, allowlist, SANs) for `tests/sim/hosts.json`; the default profile sees no simulator host.
- Out: the generator and the providers (LA-E7-02).

## Design notes

- The compose file cannot read JSON, so `infra/scripts/lib.sh` writes a compose override file from the host manifest at `stack:up` (path under `.tmp/`, not checked in).
- The consumer applies the format and the infra fail-closed rules of [README §4b](../README.md#4b-simulator-host-manifest-f74) (BD-A1-01): `lms-sim.test` stays the fixed control alias; every host ends in `.sim.test`; with no file, today's fixed lists apply until LA-E7-02 is done, then S1 removes them in its next `lib.sh` commit and a missing file counts as a bad file.
- One rule for both readers (BD-A1-53): `lib.sh` refuses an `id` that does not match `^[a-z0-9][a-z0-9-]*$` and a host that appears twice (inside one list or across providers) instead of de-duplicating it; the `sim-hosts.test.mjs` de-duplication case becomes a refusal case. The fixed fallback lists are gone.
- Bad file (BD-A1-08): it gives no simulator host (only `lms-sim.test`, no allowlist entry). Only `stack:up` and `stack:restart` in the `acceptance` profile stop on it (exit 1, before any compose call); every other command, also every `default`-profile command and `stack:down`, `stack:reset`, `stack:logs`, `stack:doctor`, runs with one warning line; `gen-certs.sh` keeps the QA leaf unchanged. `lib.sh` never exits on the file when it loads.
