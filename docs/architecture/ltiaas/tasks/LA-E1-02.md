## Goal

Create the workspace package `packages/channel-kernel` (manifest types and schema, capability catalog, registry builder, text fill, legacy projection, `legacy-wire.ts`, `fitness-scope.json`) and the manifests of `moodle`, `canvas` and `blackboard`. The app builds its channel registry by folder discovery at start. The K0 suite gets its root script line. No visible behaviour changes.

## Scope

- In: D2 manifest schema (with `storage`, `FieldSpec` without `default`, no `setup.verify`); D3 catalog and the legacy projection; D4 `loadChannelFolders`, `buildChannelRegistry`, `ChannelRegistry`, `RegistryError`, load checks 1–4, 6 and 8 (manifest side; check 5 runs on the LTI side and in the app at first use); `legacy-wire.ts` with `MANUAL_SELF_LEGACY_CHANNELS` (Moodle) and `LAUNCH_GUARD_CHANNELS` (Canvas, Blackboard); `fitness-scope.json` equal to README §4.
- Out: profile data and load check 7 (LA-E1-05); the connection DTO fields (LA-E1-06); `FieldSpec.default` (LA-E2-03).

## Design notes

- The `RegistryError.check` type of the D4 sketch lists 1–6. It must also carry 7 and 8, because load checks 7 and 8 exist (D4 list).
- Baseline manifest values come from today's adapters (`services/cogniate-app/src/providers/*.ts`) and the D3 and D6 tables: Canvas guards `canvas`, Blackboard guards `blackboardlearn`, both at the `launch` level; Moodle guards nothing; card texts equal `apps/portal/src/Integrations.tsx:21-108`.
- The product loader passes exactly one root, a constant path built from `import.meta.url`. Tests pass a second root as a function argument (D4).
