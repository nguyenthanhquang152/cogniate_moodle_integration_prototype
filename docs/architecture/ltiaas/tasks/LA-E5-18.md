## Goal

Support can group protocol events by tenant. The login and launch log lines get `tool_account_id` and, when known, `platform_id`. The lines hold ids only, never personal data.

## Files

| May edit (exclusive) | Must not edit |

| `services/lti-service/src/lti/launch.ts` | `services/lti-service/src/store/**` (S, L tasks of the same wave) |

Needs from other lanes: none.

## Scope

- In: `login_rejected`, `launch_check_failed`, `launch_accepted` and the other `launch_*` lines get `tool_account_id` when the account is known, and `platform_id` when the platform is known. `launch_accepted` gets `binding: "cookie" | "storage"` if LA-E3-02 has not added it.
- Out: `http_request`, `api_auth_failed`, `rate_limited` (LA-E5-17, LA-E5-03).

## Design notes

- An unknown account or platform gives no field (absent), not an empty string. This keeps the existing lines byte-compatible for readers that check the field set.

## Acceptance criteria

| Id | Criterion | Evidence |
| --- | --- | --- |
| AC-LA-E5-18-01 | A refused login for account `cogniate` (unknown `iss`) logs `login_rejected` with `tool_account_id: "cogniate"`. | K1-SIM |
| AC-LA-E5-18-02 | A launch with a bad signature for a known simulator platform logs `launch_check_failed` with `tool_account_id` and that `platform_id`. | K1-SIM |
| AC-LA-E5-18-03 | A valid simulator learner launch logs `launch_accepted` with `tool_account_id`, `platform_id` and `binding: "cookie"`. | K1-SIM |
| AC-LA-E5-18-04 | A login for an unknown account logs no `tool_account_id` field. | UNIT |
| AC-LA-E5-18-05 | No protocol log line of a K1 run holds a name, an e-mail or a `sub` value (K-HYG scan of the service log). | K1-SIM |
