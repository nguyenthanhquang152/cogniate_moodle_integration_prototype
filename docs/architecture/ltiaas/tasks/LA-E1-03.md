## Goal

After this task no new channel edits a shared build file. The root typecheck, the root Vitest and ESLint cover `packages/channels/*/` by globs. ESLint enforces the import table of LA-ADR-01 D1 (fitness check F3).

## Scope

- In: the two channel tsconfig files; the Vitest include `packages/channels/*/**/*.test.{ts,tsx}` (portal-side tests with the portal jsdom setup by file pattern); one ESLint block per channel glob (D1 import table) and the F1 scope; the core rule "never import a channel folder by path".
- Out: the portal parts of the build model (Tailwind `@source`, Vite `server.fs.allow` and the `@cogniate/portal-sdk` alias). No channel portal module exists before LA-E1-11, so that task adds them, and its own AC proves them.

## Design notes

- Build rulings BD-A1-16 (Reviewer-A A-LA-E1-03-01, -02, -03, -05; Reviewer-B B-LA-E1-03-01, -03), now in LA-ADR-01 D1:
  - No runtime dynamic loading in any channel file (tests too): no `import()` expression, `require()`, `import x = require()` or `createRequire`. A type-position `import('…')` follows the row of the file kind. In all code, a template literal with no `${…}` counts as a string specifier (a core `import()` of a channel path fails).
  - Closed list of channel file kinds: `manifest.ts`, `lti-profiles.ts`, `app.ts`, `app/**`, `portal/**`, `*.test.ts` at the root or in `app/`, `*.test.tsx` in `portal/`, `README.md`. Any other file is a lint error. A non-test file never imports a test file.
  - One base fence for every channel file, merged into each entry block: no `@cogniate/cogniate-app`, `@cogniate/lti-service`, `@cogniate/portal`, `@cogniate/player` (or sub-paths), no path under `services/` or `apps/`, except `kernel/ports.ts` (from `app.ts`, `app/**`) and `apps/portal/src/sdk/**` (from `portal/**`).
  - `app.ts` may import its own `./manifest.ts` and `./app/**`.
  - `tsconfig.node.json` include: `*/*.ts` and `*/app/**/*`.
