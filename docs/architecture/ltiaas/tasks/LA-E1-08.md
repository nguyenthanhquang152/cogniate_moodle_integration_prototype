## Goal

Move the Canvas developer key JSON route, the Moodle web services route, the Moodle course-shell publish work and the `.mbz` exporter into their channel folders behind capability guards, with their frozen paths, flags and error values. Extension code that needs storage gets a `PortContext` with a library-bound `ChannelSql`, never a raw database handle. The Canvas "add deployment" route becomes a kernel route guarded by `deployments.multiple`.

## Scope

- In: P5 `ExtensionRoutes` (mounted under `/app-api/connections/:id/`), P6 `PublishHook`, P7 `PackageExporter`; `PortContext` with async `seal` and `unseal`; `ChannelSql` rules (`:library_id`, manifest `storage` tables and columns); `dtoFields` limited to `legacy-wire.ts` names; the frozen body flag `createMoodleCourse`; the F5 rule `channel-sql-tables`.
- Out: the reserved pattern `/x/:extensionId` (no LA channel uses it; the mount supports it, no AC); portal panels (LA-E1-11).
