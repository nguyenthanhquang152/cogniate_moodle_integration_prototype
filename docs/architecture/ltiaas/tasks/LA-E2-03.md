## Goal

A kind A channel whose profiles all have `endpoints: admin` needs no `app.ts`: one kernel `ConnectionSetup` serves it from the manifest data. `FieldSpec.default` lets the manifest pre-fill a value that the posted value always overrides. The channel `lti-generic` (manifest, profile, README) is the first user of both.

## Scope

- In: the admin-value adapter (tool configuration rows from the manifest, strict body, `exclusive_platform` target with the admin values, staged create); create rules for admin-value channels (site rules 1–4); the `lti-generic` manifest of LA-ADR-02 D3 with A2's E3 values `content.multiple: true` (LA-ADR-05 D3b) and `registration.scopes` = the four AGS scopes (LA-ADR-05 D4), and its profile (`endpoints: admin`, `per-tenant`, `any-https`, `{platformValue}`, `path-prefix` + `opaque-bearer`, `privacyFloor: allowlist`, `platformStorage: { targetFrame: 'from-login', origin: 'authOrigin' }` by LA-ADR-05 D1 rule 1a).
- Out: grant bound values and redemption checks (LA-E2-04); DR fixes (LA-E2-02).

## Design notes

- Build rulings (A1 BD-A1-78..80): the kernel admin-value adapter gives the generic row set of app delta §3.3 when the manifest has no `setup.toolRows`; it serves every channel without `app.ts` (the LTI service refuses admin values on a `fixed` profile); `FieldSpec.default` is literal text with the only placeholder `{siteUrl}`, filled for an absent field (a posted value wins); the `lti-generic` manifest sets it on `issuer` only.
- `listOrder` of the `lti-generic` profile is above every baseline real profile, so it comes after them and before the simulation profiles (LA-ADR-01 D4).
- The folder is new in B3, after A2's E3 Must tasks of B2, so it starts with the E3 values (A2 LA-B2b items 1 and 2). Later values come from A2's companion tasks in lane K: `content.ungraded: true` (LA-E3-14, Should, after LA-H22) and `setup.connectionCheck: true` (LA-E6-04, Could).
