## Goal

For a connection whose method has the authority `verifiedAdminLaunch`, the portal verify step offers two paths: "I have an approval code" (the grant) and "Confirm from {LMS}" (the code that the LMS administrator got from the admin launch). The library user types the code; the portal calls the verify route and shows the result.

## Files

| May edit (exclusive) | Must not edit |
| --- | --- |
| `apps/portal/**` (P area: the verify panel and its texts) | every service file; `packages/channels/*/manifest.ts` (K: LA-E6-03 sets the authority values) |

## Scope

In: the panel (instructions for the LMS administrator, the code field, the submit) shown when the binding authority of the method is `verifiedAdminLaunch`; the result texts for `200` (registered), `422 VERIFICATION_CODE_INVALID`, `429 RATE_LIMITED` (with the wait time), `409 CONNECTION_NOT_PENDING`. Out: the route and the code rules (LA-E6-03).
