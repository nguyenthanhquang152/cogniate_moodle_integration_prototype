## Goal

Build one job runner for both services: queue jobs with conditional leases, fairness and bounded parallelism, and interval jobs with a single-run lease. The runner keeps one heartbeat row per instance id with a boot id, so a clean restart recovers at once and a second live process with the same id cannot send. The app outbox (LA-E4-02) and A2's E5 jobs use it.

- Out: the outbox rules (LA-E4-02, LA-E4-03); the worker process mode and the production refusal (LA-E4-05).

## Design notes

- Reviewer-A round-3 note: `stop()` deletes the heartbeat row only after the runner has stopped leasing and its in-flight runs have ended, or after `leaseMs`. So a start during the stop grace time does not mark rows uncertain without need.
- Reviewer-B round-3 note (Could): in the web process, a runner that meets `job_instance_conflict` may keep waiting (no lease, a check every 5 s) instead of turning off. The worker process still exits 1. AC-LA-E4-01-09 records this as Could.

## Acceptance criteria

| AC | Observable outcome | Evidence |
| --- | --- | --- |
| AC-LA-E4-01-01 | Lease: one conditional update takes a lease with `lease_owner` = instance id + `/` + boot id and `lease_until` = now + `leaseMs` (default 60 s); a second taker gets `false`; a result from a process with another boot id is refused (no late result). | UNIT |
| AC-LA-E4-01-02 | One in flight per key: two runners with distinct instance ids on one temporary SQLite file; one due row gives exactly one run; a higher row of the same (placement, learner subject, reporter) waits until the lower row has a recorded result. | UNIT |
| AC-LA-E4-01-03 | Fairness: `due` gives rows round-robin over partitions, oldest `next_try_at` first inside a partition; at most `parallel` runs at once; `perPartition` stays 1 and a value of 2 is refused at `addQueue`. | UNIT |
| AC-LA-E4-01-04 | Restart with a controlled clock: after `stop()` (row deleted), a new start recovers its own leases at once; after a crash (row left), a new start with another boot id takes no lease and recovers nothing until the old heartbeat is 30 s old, then goes on. | UNIT |
| AC-LA-E4-01-05 | A second live process with the same instance id (its heartbeat keeps moving) gives `job_instance_conflict`; while it waits it never takes a lease. | UNIT |
| AC-LA-E4-01-06 | `stop()` deletes the heartbeat row only after leasing has stopped and every in-flight run has ended, or after `leaseMs`. | UNIT |
| AC-LA-E4-01-07 | Interval jobs: a run starts only with a free or expired single-run lease, else the result is `skipped_lease`; an expired lease of a crashed run frees the job; `runNow(name)` returns the run result or `{ result: 'skipped_lease' }`. | UNIT |
| AC-LA-E4-01-08 | Each run (also `runNow`) has its own trace id and logs one `job_run {job, ms, result, counts}` line; an error logs its class name only, never its message. | UNIT |
| AC-LA-E4-01-09 | (Could) In the web process, a runner that meets `job_instance_conflict` keeps waiting without a lease and starts when the other heartbeat stops; the worker process exits 1. | UNIT |
