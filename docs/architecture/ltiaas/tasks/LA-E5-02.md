## Goal

The LTI service records who changed what. Every authenticated admin or operator change writes exactly one append-only `audit_event` row, in the same transaction as the change. Operators read the log through `GET /operator/v1/audit`.

## Scope

In:
- Table `audit_event` with the columns of LA-ADR-06 D4 and a trigger that refuses every `UPDATE` (`audit_event is append-only`).
- One audit writer (`insert` and `list` only). `details` at most 4 KB, after the shared `redact()`.
- Events for the existing tenant admin routes `POST`, `PATCH`, `DELETE /api/platforms…`, `POST …/deployments`, `PATCH …/deployments/:deploymentId` (actions of contract delta §5), `ok` in the change transaction, `refused` with the code after a `4xx`.
- Events for the routes of LA-E5-01 (`operator_key.issue`, `operator_key.revoke`, and `init` with actor `system:bootstrap`).
- `GET /operator/v1/audit` with the query filters of contract delta §3 (at most 500 per page, newest first, cursor); the read writes `audit.read`.
- Fitness rule F5: no `DELETE FROM audit_event` in product code outside the `audit-retention` job (the job is LA-E5-19; the rule starts now).

Out:
- `registration.complete` event (LA-E3-06, lane L, calls this writer).
- Events of the operator routes that later tasks add (each task writes its own: LA-E5-03, -04, -07, -09, -10).
- `audit-retention` job (LA-E5-19). Tenant read `GET /api/audit` (Should, LA-E5-15).
- The app audit table (LA-E5-11).

## Design notes

- An unauthenticated request writes no event (rule 1); it only logs `api_auth_failed`.
- `client_ip` follows the client address rule of LA-ADR-06 D1. Before LA-E5-03 lands, it is the socket address.
- The writer API is the only path to the table. Other lanes call it; they never write SQL for it.
- QA reads the log only through the API (`GET /operator/v1/audit`), never through the database.
