## Goal

The LTI service gets a second, internal listener for the operator API, with its own credential: one operator key per person. This task builds the listener, the `operator_key` table, the operator-key endpoints and the one trust bootstrap command `lti:operator init`. Later E5 tasks add their endpoint groups to this listener.

## Scope

In:
- Second Fastify listener on `OPERATOR_HOST:OPERATOR_PORT` (default `127.0.0.1:4110`); `service_started` logs `operator_bind`.
- `acceptance` stack: `OPERATOR_HOST=0.0.0.0` (compose env line), so the `e2e` container reaches `http://lti-service:4110`. No proxy route in any profile.
- `Authorization: OPERATOR-AUTH-V1 <key>`; key format `ltio_` + 43 base64url characters; only the SHA-256 hash is stored.
- Table `operator_key` (id, operator name, hash, created, expires, last used, revoked).
- Endpoints `GET`, `POST /operator/v1/operator-keys`, `POST /operator/v1/operator-keys/:id/revoke` (contract delta §3), with the `expiresAt` range rule (1 hour to 1 year; default 90 days).
- `npm run lti:operator -- init --name <n>`, with `--if-none` and `--replace` (LA-ADR-06 D3 "Trust bootstrap").
- `infra/scripts/lti-bootstrap.sh` runs `lti:operator init --if-none` before the bootstrap and writes `infra/.secrets/lti-operator-key` once.

Out:
- Audit events of these routes (LA-E5-02 adds the writer; this task calls it when LA-E5-02 lands, see Design notes).
- Rate-limit class `operator` and `auth_failure` (LA-E5-03).
- The other endpoint groups (LA-E5-04, LA-E5-07, LA-E5-09, LA-E5-10).
- `lti:bootstrap` and `lti:shared-platform` as API clients (LA-E5-05).
- The production refusal of a non-loopback bind (LA-E5-21).

## Design notes

- A tenant API key on the operator listener, and an operator key on `/api/*`, are unknown credentials (`401`). The two credential grammars must not share a lookup path.
- `POST …/operator-keys/:id/revoke` with the key of the same request gives `409 OPERATOR_KEY_IN_USE` (contract delta §3).
- `init` is the only direct database write of an operator key. Every other operator-key change goes through the API.
- Order with LA-E5-02: this task lands first. LA-E5-02 adds the audit event of `operator_key.issue` and `operator_key.revoke` and the `system:bootstrap` event of `init`.
- The key file mode in the `acceptance` profile is the mode of `infra/.secrets/seed.json`, which the `e2e` container already reads (LA-ADR-06 D3).
- QA command allowance for `docker compose exec lti-service npm run lti:operator -- init …` is README OC-7 (tasks README §2).
