## Goal

The LTI service CLIs stop writing `lti.db` while the service runs. `lti:bootstrap` and `lti:shared-platform` become clients of the operator API with the operator key file. Their arguments and their stdout lines stay the same, so the stack scripts do not change in behaviour.

Needs from other lanes: none.

## Scope

In:
- `lti:bootstrap --account --name [--rotate-api-key] [--rotate-signing-key]` calls the operator API (contract delta §3 "CLI mapping"):
  - account create or update;
  - API key issue when the account has no active key, or with `--rotate-api-key` (then revoke every other key: today's meaning, `services/lti-service/src/store/accounts.ts:59-62`);
  - with `--rotate-signing-key`: create a `next` key, then activate it with `force: true`.
- The one JSON stdout line `{account, created, kid, apiKey}` stays (`services/lti-service/src/cli/bootstrap.ts:30`).
- `lti:shared-platform` calls `POST /operator/v1/accounts/:id/shared-platforms` and keeps its output.
- The CLIs read the operator key from `infra/.secrets/lti-operator-key` (path inside the container as the wrapper gives it) and the operator listener address from config.
- `infra/scripts/lti-bootstrap.sh` keeps `init --if-none` (LA-E5-01) before the bootstrap call.

Out:
- `lti:operator init` (LA-E5-01; the only direct database write).
- New key commands beyond today's flags (operators use the API; operability §6).

## Design notes

- The CLI audit actor is the operator name of the key file (AP-06-12).
- A CLI run with a missing or revoked operator key exits 1 with one line that names the key file; it does not fall back to a direct database write.
- `--ensure-key-file` and `--quiet` of the wrapper (`infra/scripts/seed.sh:43-44`) keep their meaning.
- QA commands (Q-LAB-01): AC-03, AC-04 and AC-05 run `npm run lti:bootstrap -w services/lti-service -- --account <id> --name <n> [--rotate-api-key] [--rotate-signing-key]` in QA's own clone and stack (tasks README §2 form (d)); they use a fresh account, never `cogniate` of another lane. AC-07 renames `infra/.secrets/lti-operator-key` in QA's own clone for one CLI run and restores it in the test's clean-up (tasks README §2 form (e)).
