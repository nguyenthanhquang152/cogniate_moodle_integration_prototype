## Goal

A Canvas admin can install Cogniate with Canvas Dynamic Registration instead of pasting the developer key JSON. The registration creates the Canvas platform **inactive** with the connection's binding ref. The operator grant is still the ownership proof; its redemption adopts and activates the staged platform.

## Scope

In:
- Canvas profiles get `dynamicRegistration: { issuerRule: 'profile', registrationToken: 'opaque-bearer' }`.
- `issuerRule: 'profile'`: the configuration issuer must equal the profile issuer, and every endpoint must equal the filled profile value (auth and JWKS fixed; token `{serviceUrl}/login/oauth2/token`). Any other value refuses the registration; nothing is stored.
- The configuration URL is https, fetched with the guarded client; its host is the connection's site origin, its service origin, or a fixed host of the Canvas profile (`sso.canvaslms.com`).
- The registration request adds the Canvas extension members: privacy level `anonymous`, tool id `cogniate`, the vendor name; the scopes are `registration.scopes`.
- The platform is always staged: inactive, with the connection's binding ref.

Out: the optional `tokenEndpoints` trait field (only after a CANVAS-HOSTED row, LA-ADR-05 D6 "Dependency"); live rows (LA-H3).
