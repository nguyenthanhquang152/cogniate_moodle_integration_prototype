## Goal

Record the result of every frozen suite at G-BASE, per test id, so that every later step can use the differential rule of TEST-STRATEGY §4.2. Record the request rates that the new LA limits must stay above. This is the first full run on the LA base.

## Files

| May edit | Must not edit |
| --- | --- |
| `tests/ltiaas/baseline/**` (new), `docs/reviews/LA-E0-02/qa.md` | Product code; frozen test files (LA-E0-04 owns the LD-1 rewrite) |

## Scope

- In: R1 and R2 suites at G-BASE; the M1 `migration` and `snapshot-upgrade` phases; run times; engine facts and memory peaks; the `/tool/launch` and `/tool/deep-link` peak rates; the LTI request rate per rate-limit class of one T7 run.
- Out: golden outputs (LA-E0-03); the M1 `snapshot-isolated` and `storage` phases (LD-3: no storage command changes in LA).

## Design notes

- A baseline FAIL is recorded with its error and step. E0 fixes nothing. A later step is blocked only if that failure changes (TEST-STRATEGY §4.2).
- F0.4 (LD-3): no ADR-012 runtime gate (G-1 client identity) runs in an LA lane. The engine identity is a recorded fact, not a gate.
