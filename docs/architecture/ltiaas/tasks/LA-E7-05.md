## Goal

Give the simulator every behaviour that the LA acceptance tests need, each as a scenario option whose default is today's behaviour. The largest part is the platform side of Dynamic Registration (configuration document, registration endpoint, both token formats), which E2 and A2's Canvas DR need.

## Scope

- In (by need, Must first): DR platform side for the generic, D2L and Moodle-shaped configs (issuer path, `opaque-bearer` and `scope-jwt` (BD-A1-76; the simulator's own option name may stay), foreign token host, `authorization_server` off the issuer origin); score answer with `429` with and without `Retry-After`; token-endpoint `429`; memberships `429`; `403` whose body contains `Rate Limit Exceeded` (A2 LA-E5-14); DL options (item count, Cancel, `accept_multiple`, `accept_lineitem`, `accept_media_types`, the target query `cogniate_placement=ungraded` of A2 LA-E3-08); an extra `aud` value in the ID token (A2 LA-E3-12); Canvas DR with an opaque token (A2 LA-E3-09); NRPS members; platform storage (the login sends `lti_storage_target`; the auth host serves the forwarding frame with `lti.put_data` and `lti.get_data`); Should and Could: a second platform signing key, an institution administrator role, a token endpoint that answers `invalid_client` on demand.
- Out: product changes.

## Design notes

- Order inside the task: DR platform side and `Retry-After` first (E2 and E4 need them in B2–B3), then the E3 options, then the Should and Could options.

## Acceptance criteria

| AC | Observable outcome | Evidence |
| --- | --- | --- |
| AC-LA-E7-05-01 | With every option at its default, the simulator self-tests, M1 `sim` phase and M2 give the baseline results. | K1-SIM |

| AC-LA-E7-05-03 | Throttling options: a score POST gets `429` with `Retry-After: 30`, or `429` with no header; the token endpoint and the memberships endpoint can answer `429`; a score POST can get `403` with `Rate Limit Exceeded` in the body; the records show the time of each request. | K1-SIM |
