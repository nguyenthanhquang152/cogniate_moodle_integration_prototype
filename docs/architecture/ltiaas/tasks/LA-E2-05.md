## Goal

Add D2L Brightspace as data only: one channel folder with a manifest, one admin-value profile with field defaults, and a README with the source of each fact. The diff against the E2-K-done SHA changes zero core files (fitness check F2). The channel guards its product family `desire2learn` at the `registration` level.

## Files

| May edit | Must not edit |
| --- | --- |
| New `packages/channels/brightspace/{manifest.ts,lti-profiles.ts,README.md}` and its unit tests | Every other path. A needed core change stops this task and goes back to E2-K (it would fail AC-LA-E2-05-01). |

## Scope

- In: the LA-ADR-02 D4 table: profile traits, the four defaults as `FieldSpec.default`, `deployments.multiple`, `launch.windowHint: true`, `launch.topLevelContinue: false`, guarded family `desire2learn` (`registration` level), manual method with `operatorGrant`, `registration.scopes` = the four AGS scopes (A2 LA-ADR-05 D4), admin steps.
- Out: Dynamic Registration (LA-E2-06, Should); `platformStorage` (stays `null` until a live check).

## Design notes

- The QA simulator module and kit fixture of D2L are QA work (LA-E7-02, LA-E7-06); F2 classes them `sim` and `tests`.
