## Goal

Give tenants and operators a way to revoke the service keys of a scope (platform, deployment, context, resource link). The next launch of a revoked scope gets a new key value, so the activity does not lose grade return for ever. An account setting `service_key_write_scope = resource-link` closes A-T3a-04: a leaked service key can then write only the line items of its own resource link.

## Scope

- In: `POST /api/service-keys/revoke` (Bearer, `admin` scope); `POST /operator/v1/accounts/:id/service-keys/revoke`; `issue_epoch` re-issue rule; write scope check for SERVICE-AUTH-V1 writes; the audit event `service_key.revoke`; the account field `serviceKeyWriteScope` is already stored by LA-E5-04, this task enforces it.
- Out: setting `cogniate` to `resource-link` in a real stack (an operator step after one T5a and T5b regression, LA-ADR-06 D8); the `401` handling in the app outbox (unchanged, the dispatch fails and Resend works after a new launch).

## Design notes

- Epoch 0 must keep today's HMAC input byte for byte (`services/lti-service/src/store/service-keys.ts:24-38`); the input gets `epoch=<n>` only when `n > 0` (LA-ADR-06 D8).
- The write scope check runs for SERVICE-AUTH-V1 writes only: score `POST`, line item `PUT` and `DELETE`. Allowed targets: the AGS `lineitem` URL of the key's resource link, or a line item whose `resourceLinkId` equals the key's resource link. The line item lookup (one `GET`) is cached 10 minutes per (key, line item).

## Acceptance criteria

| Id | Criterion | Evidence |
| --- | --- | --- |
| AC-LA-E5-15-01 | `POST /api/service-keys/revoke {platformId}` with an `admin` key gives `200 { revoked: n }` with `n` ≥ 1; a score `POST` with a revoked service key then gives the same `401` as an unknown service key. | K1-SIM |
| AC-LA-E5-15-02 | A revoke with `resourceLinkId` revokes only that resource link: the service key of another resource link of the same platform still gets `2xx` on a score `POST`. | K1-SIM |
| AC-LA-E5-15-03 | After a revoke, the next learner launch of the same resource link shows a `services.serviceKey` in `GET /api/idtoken` that differs from the revoked value, and a score `POST` with it gives `2xx`. | K1-SIM |
| AC-LA-E5-15-04 | For epoch 0 the derived key value equals today's value for the same fixture row (golden); for epoch 1 it differs. | UNIT |
| AC-LA-E5-15-05 | With `serviceKeyWriteScope: resource-link` on the account, a score `POST` with the service key of resource link A to the line item of resource link B gives `403 SERVICE_KEY_SCOPE`; the same `POST` to A's own `lineitem` gives `2xx`. | K1-SIM |
| AC-LA-E5-15-06 | With `resource-link`, an LTIK-AUTH-V2 score `POST` to any line item of the course behaves as before (no `SERVICE_KEY_SCOPE`). | K1-SIM |
| AC-LA-E5-15-07 | A key with scopes `["launch"]` on `POST /api/service-keys/revoke` gives `403 API_KEY_SCOPE_MISSING`; every successful revoke (tenant or operator route) writes one `service_key.revoke` audit event. | K1-SIM |
