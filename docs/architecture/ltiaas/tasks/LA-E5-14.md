## Goal

When a platform throttles us, the LTI service tells the tool back end so, with a time to wait. A platform `429`, or a `403` whose body contains `Rate Limit Exceeded` (Canvas throttling), becomes `429 PLATFORM_RATE_LIMITED` with `Retry-After`. The E4 outbox then keeps the row `pending` until that time (LA-ADR-03 D7).

## Scope

In:
- Mapping (contract delta §1.3): platform `429`, or `403` with a body that contains `Rate Limit Exceeded`, gives `429` with `details.message: PLATFORM_RATE_LIMITED`, header `Retry-After` and `details.retryAfter` (seconds).
- The wait: the platform's `Retry-After` (seconds or an HTTP date), clamped to 1–3,600; 60 when absent.
- Every `/api/lineitems*` and `/api/memberships` call, and the platform token request behind them.
- Log `platform_rate_limited {platform_id, status, retry_after_s}` (warn).
- No automatic retry inside the LTI service.

Out:
- The outbox `throttled` handling and the partition pause (R, LA-ADR-03 D7).
- The LTI service's own `429 RATE_LIMITED` (LA-E5-03).

## Design notes

- Behaviour change LA-IC-11: before this task both answers were `502 PLATFORM_ERROR`. No M1, M2 or T7 test sends a `429` (LA-ADR-04 D8), so QA expects no frozen assertion change; if one appears, QA makes the reviewed test-change list at this task (plan LD-9).
- A worker from before E4 retries a `429` like the old `502` (contract delta §9), so the order with E4 does not matter.
- Other `403` answers keep today's mapping (`services/lti-service/src/platform/error-mapping.ts:18-25`).
