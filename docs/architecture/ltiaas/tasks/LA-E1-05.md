## Goal

Move the LTI profiles of Moodle, Canvas and Blackboard into `packages/channels/*/lti-profiles.ts`. The LTI service builds its profile registry from the channel folders, checks each profile against one schema with a closed trait set, and runs generic check 14 from the manifests' guarded families. `PUBLIC_MOODLE_URL` leaves the services. Wire answers and launch behaviour do not change.

## Design notes

- The `ProviderProfile` schema and its closed trait set live in `services/lti-service/src/profiles/` (lane L), not in the kernel package: load check 7 runs in the LTI profile registry.
- Until LA-E1-10, `GET /api/providers` keeps today's fields; the LTI service fills `lms` from `wireLms` inside the profile object, so `platforms.ts:309` gives the same value.
- BD-A1-21 (Reviewer-B B-LA-E1-05-01): `ProfileSource` becomes a kernel type (`@cogniate/channel-kernel`, types only); each `lti-profiles.ts` uses `import type` and `satisfies readonly ProfileSource[]`; `profiles/schema.ts` keeps `satisfies z.ZodType<ProfileSource>` against the kernel type, and `profiles/types.ts` re-exports it. The kernel lines: RQ-1 to K, or RQ-2 to L (the Lead decides).
- BD-A1-23 (Reviewer-A A-LA-E1-05-03): load check 7 refuses a profile that is not a key of `BASELINE_PROFILE_WIRE_LMS` when its `listOrder` is not above the largest baseline `listOrder` (simulation profiles included; 70 today), computed from the definitions whatever the simulation setting; the `channel_registry_invalid` line names the profile id and the bound. Order stays: real before simulation, then `listOrder`, then id.
- BD-A1-22 (Reviewer-A A-LA-E1-05-02; ratified by A2 as BD-A2-21; L adds `PRIVACY_FLOOR_NONE_PROFILES` to `legacy-wire.ts` by RQ-2): load check 7 allows `privacyFloor: 'none'` only on the profiles of the frozen list `PRIVACY_FLOOR_NONE_PROFILES` (`legacy-wire.ts`, one entry `standard`); the launch keeps every claim only when the value is exactly `none` (fail closed). Unit tests: a new profile with `none` stops the start; an unknown value minimizes.
- Baseline profiles for load check 7 (BD-A1-06): the frozen map `BASELINE_PROFILE_WIRE_LMS` of `legacy-wire.ts` with exactly eight pairs: `standard` → `null`; `canvas-cloud-production`, `canvas-cloud-beta`, `canvas-cloud-test`, `canvas-self-hosted`, `canvas-sim-cloud` → `'canvas'`; `blackboard`, `blackboard-sim` → `'blackboard'`. The check runs in both directions: a profile whose id is not a key must not have `wireLms`; a profile whose id is a key must have `wireLms` equal to the map value (`null` is a value; a missing `wireLms` fails). No other core list of profile ids.
