## Goal

Add the app migration with `placement`, `learning_record`, `record_dispatch`, `job_instance` and `job_lease`, and copy every `score_sync` row into `record_dispatch` with the same id and state (design number `014`). The launch upserts the placement with the resource link. The commit transaction writes a `final` learning record for a new best result, and the outbox on the job runner creates and moves the dispatch rows with the ADR-010 and P2 rules. Every answer of the results API, Resend and the play status stays the same.

## Design notes

- Until LA-E4-03 lands, the outbox calls today's score send code through the reporter port; the two tasks land in this order inside lane R.
- LA-IC-09: QA changes the T5b P5 fixture to delete the same failed row in `record_dispatch` (QA form (j) of tasks README §2). The assertions stay.
- Row errors (BD-A1-10; LA-ADR-03 D7 "Row errors"): the outbox `run` catches every error of its own row and moves the row (a try counted and a later `next_try_at`, or `failed` at the end of the 24 h window), as the M1 `send()`. The runner's row cooling (LA-E4-01) is only a backstop.
- Stop (Reviewer-A note on LA-E4-01): the outbox does not abort a POST in flight when `ctx.signal` fires; the signal only stops its next step, so a normal restart makes no uncertain row. The app awaits `runner.stop()` before it closes the database.
