## Goal

A tool signing key moves through the states `next` → `active` → `retired`, and ends as `removed`. A new key is published before it signs, and a retired key stays published for 30 days from its retirement. The A-T0-16 rotation tests close the deferral.

## Scope

In:
- States and columns of LA-ADR-06 D7; exactly one `active` key; at most one `next` key (`409 SIGNING_KEY_NEXT_EXISTS`).
- Migration rule (A-LAD-06): an `active` row gets `published_at = activated_at = created_at`; a `retired` row created less than 30 days before the migration gets `retired_at` = migration time; an older `retired` row becomes `removed` with `removed_at` = migration time. The published set does not change.
- JWKS order: `active`, then `next`, then `retired` while `now < retired_at + 30 days`; `Cache-Control: public, max-age=300` stays.
- Publish lead time `SIGNING_KEY_PUBLISH_LEAD_S` (default 86,400 s; minimum 600 s); else `409 SIGNING_KEY_NOT_PUBLISHED_LONG_ENOUGH`; `{force: true}` skips it, and the audit event has `forced: true`.
- Activate in one transaction (old `active` → `retired` with `retired_at = now`; `next` → `active`); the JWK cache of LA-E5-08 must not sign with the old key after the commit.
- Retire immediate: `POST …/signing-keys/:kid/retire {immediate: true}` on a `retired` key sets `removed`; on the `active` key `409 SIGNING_KEY_ACTIVE`.
- Endpoints `GET`, `POST /operator/v1/accounts/:id/signing-keys`, `POST …/:kid/activate`, `POST …/:kid/retire`, each with its audit event.

- The job module `signing-key-cleanup` (moved here from LA-E5-19, LD-10): at start, then daily; `retired` → `removed` at `retired_at + 30 days`; it zeroes the private blob of every `removed` row that still has one, also the rows that the migration marked `removed`. LA-E5-19 (S1) registers it on the runner.

Out:
- The runner wiring and the job registration (LA-E5-19, S1). Scheduled rotation (Should, LA-E5-20).
- `lti:bootstrap --rotate-signing-key` as an API client (LA-E5-05).

## Design notes

- Today the JWKS keeps a retired key while `now − created_at < 30 days` (`services/lti-service/src/store/tool-keys.ts:30-36`). After this task the clock starts at `retired_at` (the J-2 defect is gone).
- LA-IC-10 (signing keys): the golden `GET /lti/keys/:account` of an upgraded stack is equal before and after the upgrade. QA checks it; no assertion changes are expected (plan LD-9 list only if QA finds a test that counts keys after an old rotation).
