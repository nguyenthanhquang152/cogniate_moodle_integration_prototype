## Goal

Prove once that the pilot can restore from the cold backup of ADR-012 §8, with the key versions that the backup record names. The drill records the measured recovery time (RTO) and the backup age (RPO) as evidence for LA-H8. The task changes no product code and no storage command (LD-3).

## Files

| May edit (exclusive) | Must not edit |
| --- | --- |
| QA-E2E evidence under `docs/reviews/LA-*/` (path chosen by the Lead) | any product file, `infra/**`, any storage command (LD-3) |

Needs from other lanes: Docs writes the runbook text from [operability §7](../operability.md#7-backup-and-restore) in E8; this drill checks it. The Lead confirms that this Should drill may use the existing ADR-012 commands unchanged (as AC-M1-23 does); else the drill moves to LG with LA-H8 option (b) (A-LAB-08).

## Scope

- In: one drill on a **fresh QA project made for the drill** (its own clone and `COMPOSE_PROJECT_NAME`, TEST-STRATEGY §5.2), using tasks README §2 form (g): back up that project, make one marker change, restore the backup into the **same** project, start, check, launch and score, record the times. Then remove the drill project.
- Out: a restore into another compose project: `stack:data-restore` refuses it (`project_mismatch`, `infra/scripts/stack-data.mjs:178`; ADR-011 §14), and LD-3 forbids a storage-command change (B-LAB-03). A restore on a second host or Docker context with the same project name is the operator drill of the runbook (operability §7.3), not a QA lane task. An online backup (not in LA). The RPO and RTO targets (LA-H8 decides).

## Design notes

- `npm run stack:reset` is not part of the drill: it also deletes the secret files and `infra/.data/backups/` (`infra/scripts/stack-reset.sh:2-4`). The marker change proves that the restore replaced the data.
- Readiness: LTI `/readyz` when LA-E5-17 is built, else `/healthz`; the app `/healthz` (the app `/readyz` exists only with LA-E4-07).
