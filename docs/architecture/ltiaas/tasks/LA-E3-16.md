## Goal

LA-ADR-05 D6 promises that Canvas Dynamic Registration "removes the JSON paste and the typed client id". Today the Canvas wizard always creates the method `manual`, always shows the developer key JSON, and shows an empty binding form. This task gives the Canvas wizard a Dynamic Registration path. The manual path does not change.

## Scope

In:
- **Method choice at create.** When the Canvas manifest's `registration` list has the method `dynamic`, the create step shows two choices: "Developer key" (method `manual`, the default) and "Dynamic Registration" (method `dynamic`). The list comes from the manifest, not from a constant in the wizard. With `manual`, the create request is the same as today, byte for byte.
- **Registration URL instead of the JSON.** A pending `dynamic` connection shows the registration URL step: the copy button, the expiry, and "Get registration URL" (renew), as the shell wizard's `ShowStep` does (the same app route). It does not show the developer key JSON. A pending `manual` connection shows today's JSON step, unchanged.
- **Staged binding form.** A pending `dynamic` connection with a staged platform in its DTO shows the binding form of the three `dynamic` binding rows (Client ID, Deployment ID, Approval code). Client ID and Deployment ID are pre-filled from the DTO (`platform.clientId`, `platform.deploymentIds[0]`) and stay editable; the approval code is empty. Before the platform is staged (no platform in the DTO), the step says "Finish the registration in Canvas. Then this page shows the values to check." and has no inputs.
- Texts in Simplified Technical English, in `canvas-steps.json`.

Out:
- The LTI service rules (LA-E3-09) and the app's staged registration side (LA-E2-04).
- Any change to the manual path, the shell wizard, or another channel.

## Design notes

- The operator grant proves the values (LA-ADR-05 D6 "Authority"; BD-A2-89). Pre-filled values only save typing: the grant redemption compares them with the granted values, so an edited or wrong value cannot activate a platform.
- LD-9: no intended change. The manual DOM, its texts and its requests stay byte for byte, so the M2 Canvas e2e and the frozen Canvas acceptance tests do not change, and there is no LA-IC for this task.
- Hosted Canvas (BD-A2-106): `canvas-steps.json` `dynamic.methods.dynamic.help` is "Copy one registration URL into {LMS}. Cogniate gets the Client ID and the Deployment ID. For Instructure-hosted {LMS}, use Developer key. Cogniate does not support this method there yet." The choice stays for every Canvas type (no filter by type). AC-LA-E3-16-01 asserts this string. LD-9: none. The text is inside the method fieldset, which the AC-LA-E3-16-05 snapshot removes; a manual-only manifest shows no fieldset.
- Reuse, do not copy: if the registration-URL part of `ManifestWizard.tsx` is not exported for channel wizards, move it to the portal SDK as an export with no behaviour change, and use it in both places.
