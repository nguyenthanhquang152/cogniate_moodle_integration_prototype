# T1: Monorepo skeleton and local HTTPS stack with Moodle 5.2

Owner: Author (in build). Reviewers: A + B. QA: black-box. Depends on: T1-spike. Design: [`../local-stack.md`](../local-stack.md), ADR-005, ADR-008. QA rules: [`README.md`](README.md).

Round 2 note: this file folds in the Lead-approved changes (LC-T1-01 CA and leaf certificate, incl. the A-T1-01 CA limits, LC-T1-02 public URL config, AC-T1-13, demo commands, fixtures check) and the QA hooks H1, H2, H3, H4, H7, H8, as sent to the Author. The other T0 round-2 changes do not change T1.

## Goal

One command starts a production-like local stack: Moodle 5.2.4 behind TLS, four host names on three sites, stub Node services, and a Playwright runner on the same network. The repo has a working `npm run check`. A human can start a demo and look at it in a browser.

## Scope

In:

- Root workspace: `package.json` (npm workspaces `packages/*`, `services/*`, `apps/*`), `package-lock.json`, `tsconfig.base.json`, `eslint.config.js`, `vitest.config.ts`, `.gitignore`, `.env.example`. Root lint, typecheck and Vitest exclude `tests/**`.
- `npm run check` = ESLint + `tsc --noEmit` per workspace + Vitest.
- `infra/compose.yaml`: `proxy` (Caddy), `postgres`, `moodle`, `lti-service`, `cogniate-app`, `e2e` (profile `test`).
- **LC-T1-01 TLS:** `gen-env` runs `infra/scripts/gen-certs.sh` with `openssl` **before** any container starts: a dev CA (`infra/.certs/ca.key`, `root.crt`) with `nameConstraints = critical, permitted;DNS:test` and a life of ≤ 1 year, and one leaf certificate (`stack.crt`, `stack.key`, SAN = the four host names) that does not outlive the CA. If an existing CA has no name constraint or has expired, `gen-certs.sh` makes a new CA and leaf, and prints that a human who trusted the old root must trust the new one. `stack:reset` does not delete `infra/.certs/`. Caddy loads the static leaf (no `tls internal`). `ca.key` is never mounted into a container.
- **LC-T1-02 public URLs:** `.env` has `PUBLIC_PORT` and `PUBLIC_MOODLE_URL`, `PUBLIC_LTI_URL`, `PUBLIC_APP_URL`, `PUBLIC_CONTENT_URL`. Compose passes them to every container. Code reads them with `loadPublicUrls()` from `@cogniate/shared`. No URL literals in code.
- Trust: Moodle `moodledata/moodleorgca.crt` = Alpine CA bundle + `root.crt`; Node `NODE_EXTRA_CA_CERTS=/certs/root.crt`; e2e Chromium through NSS.
- Moodle: `SITE_URL = PUBLIC_MOODLE_URL`, `SSLPROXY=true`, port 8080 not published.
- Provisioning `npm run seed` (idempotent): users `admin`, `cg_teacher`, `cg_student`, `cg_student2`; courses `COGNIATE-DEV-101` and `COGNIATE-DEV-102` with completion tracking on and the same enrolments (teacher = editingteacher, students = student); product WS service `cogniate_integration` (9 functions of spike §3) with a token; `noemailever=1`.
- Dev-only Moodle curl settings (as in the code, A-T1-06):
  - Blocked hosts (`curlsecurityblockedhosts`) = the Moodle default list with only `STACK_SUBNET` cut out. `172.16.0.0/12` is split around the subnet; every other default entry stays.
  - Allowed ports (`curlsecurityallowedport`) = `443` only, plus `PUBLIC_PORT` if it is not 443. Port 80 is removed.
  - Inside the subnet only the proxy listens on 443, so Moodle can reach only the proxy.
- Stub services: `GET /healthz` on the LTI, app and content hosts, returning `{status, service, knobs}`.
- **H1 separate checkout:** all state inside the checkout (`.env`, `infra/.certs/`, `infra/.secrets/`, `infra/.logs/`, `infra/.data/`, `.tmp/`). `COMPOSE_PROJECT_NAME` (default `cogniate-stack`), `PUBLIC_PORT` and `STACK_SUBNET` (default `172.28.0.0/16`) from env; volume names use the project name.
- **H2 seed output:** `seed` writes `infra/.secrets/seed.json` (mode 600, git-ignored, format `cogniate-seed/1`): URLs, Moodle users (username, password, id), course ids by shortname, WS services (product and QA oracle: service, username, userid, token, functions). Later tasks add keys and never rename or remove keys.
- **H3 test knobs:** `npm run stack:restart -- <service> [--env K=V ...]`. The service gets the knobs, logs `test_knob_active {name, value}`, and `/healthz` lists them. Without `--env` the defaults come back.
- **H4 QA oracle:** a second, QA-only WS service `cogniate_qa_oracle` (own user and token, in `seed.json`) with `gradereport_user_get_grade_items`, `core_completion_get_activities_completion_status`, `core_enrol_get_enrolled_users`, `core_course_get_contents`, `core_course_get_courses_by_field`, `core_course_update_courses`. Dev and test only.
- **H7 logs:** services write JSON lines to `infra/.logs/<service>.jsonl` (`lti-service`, `cogniate-app`, `cogniate-content`) and stdout: `{ts, level, service, event, trace_id, ...}`. Every event has `trace_id`: request events use the request trace id; lifecycle events with no request (`service_started`, `test_knob_active`, `service_stopping`) use one boot trace id per process. T1 events: `service_started`, `test_knob_active`, `http_request {method, path, status, ms, trace_id}`, `service_stopping`. Kept across restarts. `stack:reset` deletes them. Git-ignored.
- **H8 QA project:** `tests/` is a separate npm project owned by QA. `npm run test:acceptance` and `test:e2e` run `npm ci --prefix tests` and the QA scripts in the `e2e` container. The `e2e` container mounts the repo, `infra/.secrets` and `infra/.logs` read-only, and only `root.crt` and `stack.crt` of `infra/.certs`. It sets `NODE_EXTRA_CA_CERTS` and the four `PUBLIC_*_URL` values.
- **Demo:** `npm run demo` (gen-env, build, stack:up, seed; prints URLs and user names). `npm run demo:browser` (throwaway Chrome profile in `.tmp/` with `--host-resolver-rules` for the stack names and `--ignore-certificate-errors-spki-list` for our leaf only; nothing changes on the Mac).
- **Fixtures:** `COURSE_FIXTURES_DIR` (default `docs/raw/data/courses`), `npm run fixtures:check` against `infra/fixtures/courses.sha256`.
- Other scripts: `stack:up`, `stack:down`, `stack:reset`, `stack:logs`, `stack:moodle-reach-check`, `stack:node-reach-check`.
- `@playwright/test` pinned to `1.56.0`.
- `infra/README.md` with one command table (command, when to use it, what it deletes or keeps).

Out: any LTI logic (T2), app logic (T4a, T4b), QA test files.

## Files owned

Root build files, `infra/**`, `services/*/` stubs, `packages/shared/**` (URL config, logger).

## Acceptance criteria

- **AC-T1-01** On a clean clone with no `node_modules`: `npm ci && npm run check` exits 0.
- **AC-T1-02** With no stack volumes and **the images already pulled**: `npm run stack:up && npm run seed` exits 0 in ≤ 15 min and prints the four URLs. QA records the pull time and image digests separately.
- **AC-T1-03** From the `e2e` container: `GET {PUBLIC_MOODLE_URL}/login/index.php` → `200` with the Moodle login form. The TLS chain verifies against `infra/.certs/root.crt`. Without the CA, verification fails.
- **AC-T1-04** From the `e2e` container: `GET /healthz` on the LTI, app and content URLs → `200` JSON with `status: "ok"`, the service names `lti-service`, `cogniate-app`, `cogniate-content`, and `knobs: []`.
- **AC-T1-05** `npm run stack:moodle-reach-check` runs Moodle's own `download_file_content('{PUBLIC_LTI_URL}/healthz')` in the Moodle container and prints the JSON body.
- **AC-T1-06** `core_webservice_get_site_info` with the product token → `release` starts with `5.2`, `siteurl` = `PUBLIC_MOODLE_URL`, and `functions` has the 9 names of spike §3.
- **AC-T1-07** A Playwright login as `cg_teacher` works. `MoodleSession` has `Secure = true`. A wrong password does not sign in.
- **AC-T1-08** In `COGNIATE-DEV-101` and `COGNIATE-DEV-102`: `cg_teacher` is editing teacher, `cg_student` and `cg_student2` are students. Completion tracking is on in both.
- **AC-T1-09** Exactly one published port: `127.0.0.1:443` (or `PUBLIC_PORT`).
- **AC-T1-10** `npm run stack:reset && npm run stack:up && npm run seed` gives a fresh site (only the site course and the two courses), the passwords in `.env` still work, and `infra/.certs/` is unchanged (same CA fingerprint).
- **AC-T1-11** No secrets in git: every `.env*` file (not `.env.example`), `infra/.certs/`, `infra/.secrets/`, `infra/.logs/`, `**/.data/` and `.tmp/` are git-ignored (`git check-ignore`). `git grep` for every value in those files finds nothing. `.env.example` has names only.
- **AC-T1-12** `npm run seed` twice in a row exits 0 both times and makes no duplicate users, courses, enrolments, services or tokens (the WS token values in `seed.json` stay the same).
- **AC-T1-13** On a first run and after `stack:reset`: `fetch('{PUBLIC_MOODLE_URL}/login/index.php')` from inside the `lti-service` and `cogniate-app` containers returns 200 (`npm run stack:node-reach-check`).
