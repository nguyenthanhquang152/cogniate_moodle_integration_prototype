# T6: Portal UI — Integrations, Connect wizard, Courses, Publish, Results

Owner: Author. Depends on: T4b1, T4b2 (API), T5b (results). Contract: [`../contracts/cogniate-app-api.md`](../contracts/cogniate-app-api.md) §2–5. Look: `docs/research/ui/dev-portal-integrations.png`, `.research_cache/dev-portal-app.css`. Stack and dev loop: ADR-008.

## Goal

A Cogniate user does every portal step of the flow in a UI that looks like the existing dev portal.

## Scope

In (`apps/portal`, served by `cogniate-app` at `PUBLIC_APP_URL`):

- Sign-in page (mock login).
- App frame like the screenshot: sidebar (Dashboard, Company, Integrations, Assets, Libraries, Analytics; Settings, Logout; user chip), library selector. Only Integrations and Libraries → Courses work; the others show "Not part of this prototype".
- **Integrations page**: "Integrations", "Connect your favorite tools to your course library.", pills (All, LMS Publishing, LLM/AI, Creative, Knowledge), 3-column card grid. Moodle card: "Export SCORM packages and sync course content with your Moodle LMS." and "Connect". Other cards: button disabled, tooltip "Not part of this prototype". With one or more connections: no "Connect" pill; instead the status badge of the newest connection: "Waiting for Moodle" (`pending`, registration link still valid), "Link expired" (`pending`, link expired), "Registered — activate in Moodle" (`registered`), "Connected" (`connected`), "Disconnected" (`disabled`), a "Manage" button, and a secondary link "Connect another site" (a library may connect several Moodle sites). If `lastError` is set, the card and the connection page show its server `title` and `action`, the code and the trace id.
- **Connect wizard**: site URL and name; method ("Automatic (recommended)" = dynamic, "Manual"); dynamic: the registration URL with a copy button, numbered Moodle steps, live status (poll 5 s), "Make a new URL"; manual: tool values with copy buttons, then a form for the six Moodle values (https, issuer = site origin, endpoints on the issuer origin). The dynamic steps end with a help line: "If the connection failed and Moodle shows a Pending tool 'Cogniate (<library>)' that you did not activate, delete it in Manage tools and connect again." The dynamic steps include the choice page: "If Moodle asks to update an existing tool or register a new one, click Register as a new external tool. Cogniate refuses an update." The Moodle steps of both methods are **data** (`apps/portal/src/connect/moodle-steps.json`: step id, text, Moodle menu path, exact Moodle 5.2.4 labels), rendered by the wizard and read by T7.
- **Stable hooks:** the six manual-connect inputs have `name` = the contract keys (`issuer`, `clientId`, `deploymentId`, `authenticationEndpoint`, `accessTokenEndpoint`, `jwksUrl`); each tool-configuration row has `data-key` (app contract §4.1); each wizard step element has `data-step-id` = its `id` in `moodle-steps.json`.

- **Results view** per publication: learner label, activity, best outcome, score, Moodle sync status (with history on expand), gradebook value, "Refresh from Moodle", "Resend" on `failed` and `conflict` rows, the conflict text.
- Design tokens as CSS variables mapped in Tailwind; DM Sans from `@fontsource/dm-sans`.
- Component tests (Vitest + Testing Library) for the wizard and forms.

Routes: `/signin`, `/integrations`, `/integrations/moodle/connect`, `/integrations/moodle/:connectionId`, `/libraries/courses`, `/libraries/courses/:courseId`, `/libraries/courses/:courseId/publish`, `/publications/:publicationId/results`.

Out: tool pages (server-rendered), mobile polish, i18n, course shell (T8).

## Acceptance criteria

All by Playwright at `PUBLIC_APP_URL` after `npm run build && npm run stack:up && npm run seed`.

- **AC-T6-01** Sign in as Thanh → Integrations shows the title, subtitle, five pills, and ≥ 9 cards in 3 columns at 1440 px. The Moodle card has the text "Export SCORM packages and sync course content with your Moodle LMS." With no connection it has an enabled "Connect"; with a connection (the usual state in a shared stack) it has the status badge, "Manage" and "Connect another site", and no "Connect" pill. QA checks the state that matches `GET /app-api/connections`.
- **AC-T6-02** Look: `body` `background-color` = `rgb(11, 10, 15)` ± 1 (`hsl(252 20% 5%)`); the active pill `background-color` = `rgb(166, 103, 228)` ± 1 (`hsl(270 70% 65%)`); `body` `font-family` starts with "DM Sans"; cards have `border-radius` 12 px. A screenshot is attached next to `docs/research/ui/dev-portal-integrations.png`.
- **AC-T6-03** No request leaves `PUBLIC_APP_URL` while the portal loads.
- **AC-T6-04** Dynamic connect: the wizard shows a registration URL that matches AC-T4-07 and a working copy button (clipboard = URL). Before the registration the status is "Waiting for Moodle". After the admin registers (QA in a second page), the status becomes "Registered — activate in Moodle" within 10 s without a reload.
- **AC-T6-05** Manual connect: the wizard shows the 16 rows of app contract §4.1 in order, each with its `key` as `data-key` and a copy button whose clipboard text is the row `value`. `http://moodle.test` as issuer, or a JWKS URL on another origin, shows an inline error. Valid values → "Registered". The six input fields for Moodle's values have `name` = the contract keys.
- **AC-T6-06** Upload: with the network slowed by CDP `Network.emulateNetworkConditions`, a `role="progressbar"` with a growing `aria-valuenow` appears, then the report with "SCORM 1.2", "Mastery score 70" and the external hosts warning. A `PATH_TRAVERSAL` zip shows the server's reason `title` and the reason's `path` (`../evil.html`) visibly (the portal does not invent its own sentence), and makes no version.
- **AC-T6-07** The Publish dialog lists only registered or connected connections. After "Publish", the course shows "Available in Moodle" and the teacher text.
- **AC-T6-08** Results (after T5b): the SCORM publication shows `cg_student` "Passed 100" and `cg_student2` with their best outcome and "Sent". "Refresh from Moodle" fills the gradebook column.
- **AC-T6-09** `@axe-core/playwright` on Integrations, wizard, Courses, Publish dialog and Results: no `serious` or `critical` violation. The wizard and dialog work with the keyboard only (Tab, Enter, Esc); focus returns to the opener on close.
- **AC-T6-10** Signed out: each route above redirects to `/signin`. "Logout" clears the session (`GET /app-api/me` → `401`).
- **AC-T6-11** "Download SCORM package" on the SCORM course downloads a file with the same SHA-256 as the uploaded zip. The HTML course has no such button.
- **AC-T6-12** `moodle-steps.json` equals the content above (same ids, order, text, labels, `optional` values). The wizard shows its steps in order for both methods: each step element has `data-step-id` = the step `id` and shows the step `text` with `{libraryName}` replaced. The dynamic list has the choice-page step `choose-register-new` (`optional: true`, "Register as a new external tool") and, after `activate-tool`, the step `edit-tool-settings` with "Tool configuration usage" → "Show in activity chooser and as a preconfigured tool" and "Default launch container" → "New window".
- **AC-T6-13** A course titled `<b>x</b>` and a manifest title `<img src=x onerror="window.__xss=1">` show literally in Courses, Publish and Results; `window.__xss` is undefined.
- **AC-T6-14** Setup: QA makes fresh rows in T6 setup by running the recipes of AC-T5-31 (`conflict`), AC-T5-32 (`failed`, before re-enrolment) and AC-T5-33 (teacher override), each in its own activity. Results: the `conflict` row of AC-T5-31 shows "Moodle has a grade with a newer time" and a "Resend" button. The `failed` row of AC-T5-32 (before re-enrolment) shows the error and "Resend"; after QA enrols the learner again, "Resend" sets the row to "Pending" and then "Sent" without a reload. The AC-T5-33 row shows "Moodle keeps another grade, for example a teacher override" after "Refresh from Moodle". The sync history of a row lists every sync with its status.
