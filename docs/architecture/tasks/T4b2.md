# T4b2: Content picker, launch handoff, player shell, tool page security

Owner: Author. Depends on: T3a, T4b1. Contract: [`../contracts/cogniate-app-api.md`](../contracts/cogniate-app-api.md) §6, §12. Security §3, §4, §5, §6, §7 (output), §8. Flows §6b, §6c (up to `/play`).

## Goal

A teacher picks a course in Moodle. A learner launch lands on the player shell with an attempt. Every tool page has the right frame, form and referrer rules, and the handoff cannot be replayed or redirected.

## Scope

In: `/tool/launch`, `/tool/deep-link`, `/tool/picker/*`, player shell `/play/{playId}` (header, runtime iframe tag, status poll) and `/play/{playId}/embedded`, `/app-api/play/{playId}/status`, handoff rules (security §4), attempt rule after a rebind (data-model §2), page headers, dev helper `npm run seed:lti-activity -- --type <typeId> --course <shortname> --name <name> --url <toolUrl>`. Optional H11: `npm run stack:snapshot <name>` and `stack:restore <name>` for all stack volumes, so later suites can start from the "T4b2 state".

Out: content host, runtimes, outcome, score sync, results rows (T5a).

## Design notes

- Store the ltik encrypted only in the picker session. The play session holds no ltik.
- Role check for the picker: a role that ends with `#Instructor`, `#ContentDeveloper` or `#Administrator`.
- The picker submit uses `POST /api/deeplinking` and renders its own form with a nonce script.

Tool page security:

- **AC-T4-21** (pass 2, after the AC-T4-18 setup) Headers (security §5): the picker GET has `frame-ancestors {PUBLIC_MOODLE_URL}`; the picker POST result has `form-action` = the Moodle origin; `/play/<id>` has `frame-ancestors 'none'`; `/play/<id>/embedded` has `frame-ancestors {PUBLIC_MOODLE_URL}`; error pages (for example the AC-T4-18 page) have `frame-ancestors https:` and `form-action 'none'`. All have `Referrer-Policy: same-origin`, a `script-src 'nonce-…'` where they have scripts, no `X-Frame-Options` on the framed pages, and no `Set-Cookie`.
- **AC-T4-22** `POST /tool/picker/<id>` with `Origin: https://evil.test`, with `Origin: null`, and without `Origin` → `403`, `csrf_rejected` logged, the picker is not used, and no deep-linking call.
- **AC-T4-28** A course titled `<b>x</b>` and an uploaded SCORM package with manifest title `<img src=x onerror="window.__xss=1">`, published; a Moodle activity named `<i>y</i>`. The picker and the player shell show these texts literally, and `window.__xss` is undefined in every page.
- **AC-T4-29** `GET /app-api/play/<unknown id>/status` → `404`. The library B session gets `404` for `GET /app-api/publications/<Thanh publication id>` after the launches above (no stats leak).
- **AC-T4-32** (pass 2, after the AC-T4-18 setup) Every tool page error shows a code, a trace id and one action line, with `data-error-code`, `data-trace-id` and a non-empty `data-error-action` element. The trace id is in the matching log event: `launch_rejected` (AC-T4-18, AC-T4-27), `handoff_rejected` (AC-T4-24), `picker_rejected` (AC-T4-20, AC-T4-26), `deep_link_rejected {reason: "not_deep_linking"}` (the `403` page of AC-T4-20).
