# T2: LTI service core — platforms, keys, OIDC launch, ltik, ID token API

Owner: Author. Depends on: T1, T5-spike done. Contract: [`../contracts/lti-service-api.md`](../contracts/lti-service-api.md) §0 (T2 rows), §1, §2.1–2.3, §2.5, §3.1, §3.9, §5, §7. Security: [`../security.md`](../security.md) §2, §3, §8, §9. QA rules and knobs: [`README.md`](README.md).

## Goal

Moodle launches the LTI service with LTI 1.3. The service runs all checks and redirects to the tool with a ltik. A back end reads the LTIAAS-shaped ID token. Platforms are registered by API.

## Scope

In:

- `services/lti-service` (folders per ADR-008): SQLite with migrations, config from env and `loadPublicUrls()`, JSON logs (events of contract §5).
- Tool accounts, one RSA key each, bootstrap CLI (contract §7). Seed makes `cogniate` and `qa-second`; API keys in `infra/.secrets/lti-api-key.<account>` and their paths in `seed.json` (key `lti.apiKeyFiles`).
- `GET /lti/keys/{toolAccountId}`.
- Auth middleware for the three schemes (contract §1.2). `SERVICE-AUTH-V1` returns `401 INVALID_SERVICE_AUTH_AUTHORIZATION_HEADER` for every key until T3a.
- Error shape and codes (contract §1.3). HTML error pages with code, trace id, action line.
- Platforms API `GET`, `POST`, `GET /:id`, `PATCH /:id` with the issuer-origin rule (security §2.4).
- `GET|POST /lti/login/{toolAccountId}`, `POST /lti/launch/{toolAccountId}` (security §2.1, §2.2, incl. the OIDC `error` case and the help texts).
- Launch store, ltik (`LTIK_TTL_SECONDS`), `GET /api/idtoken` (+ `raw=true`), mapping of contract §3.1 (no `serviceKey` yet).
- `packages/shared` http-client with the SSRF guard (security §9). The platform JWKS goes through it (`createLocalJWKSet`, no `jose` remote fetch).
- Dev seed `npm run seed:lti-manual` (idempotent): in Moodle (PHP CLI, `lti_add_type`) the tool "Cogniate (seed)" with the LTI service URLs for account `cogniate`, `launchcontainer=4`, `coursevisible=2`, deep linking on, `gradesynchronization=2`, `memberships=1`, send name/email 0; activities "Seed activity" (`COGNIATE-DEV-101`) and "Seed activity 102" (`COGNIATE-DEV-102`), tool URL `{PUBLIC_LTI_URL}/lti/launch/cogniate?resource=seed`, accept grades on, maximum grade 100. It registers the platform with `POST /api/platforms` (deployment id = tool type id). **H9:** if the platform was deleted, a rerun makes it again. It writes `{ typeId, clientId, deploymentId, cmids, platformId }` to `seed.json` (key `ltiSeed`).
- **H6 and sink:** compose profile `acceptance` (local-stack §3): `evil.test` sink and `qa-platform.test` static host, second leaf certificate, allowlist entries for this profile only. `npm run test:acceptance` uses this profile.

Out: Deep Linking, AGS, NRPS, service keys (T3a), dynamic registration (T3b), app pages (T4b).

## Design notes

- Keep the 12 checks as small functions with one unit test each (pass + fail). Reviewer-A maps them to security §2.2.
- Mark the state as used in the same transaction that reads it.
- Clock skew 60 s. Unit tests sign test tokens with a local test key; no network in unit tests.
- The tool URL `{PUBLIC_APP_URL}/tool/launch` is still a stub in T2. QA reads the redirect URL; it does not need the page.

## Acceptance criteria

Setup: `npm run stack:up && npm run seed && npm run seed:lti-manual`, with the `acceptance` profile. Values from `seed.json`.

Keys, platforms, routing:

- **AC-T2-01** `GET /lti/keys/cogniate` → `200 application/json`, `keys` ≥ 1, each with `kty=RSA`, `kid`, `alg=RS256`, `use=sig`, `n`, `e`, and no `d`, `p`, `q`, `dp`, `dq`, `qi`. `GET /lti/keys/unknown` → `404`.
- **AC-T2-02** `POST /api/platforms` (Bearer `cogniate`) with a valid body → `201` with all fields of contract §3.9. The same call again → `409 PLATFORM_ALREADY_EXISTS`. `GET /api/platforms?clientId=` returns it. No header → `401 INVALID_AUTHORIZATION_HEADER`. Wrong key → `401 INVALID_LTIK_AUTH_AUTHORIZATION_HEADER`. The `qa-second` key sees an empty list and gets `404` for `GET /:id`.
- **AC-T2-18** `qa-second` registers the **same** issuer + client id as the seed platform → `201` (its own record). A `cg_student` launch of "Seed activity" still lands with a ltik that works only with the `cogniate` API key (`qa-second` key + that ltik → `401`).
- **AC-T2-29** `POST /api/platforms` with `authConfig.key = https://evil.test/jwks` (issuer `PUBLIC_MOODLE_URL`) → `400 PLATFORM_URL_NOT_ON_ISSUER_ORIGIN`. The same for `accesstokenEndpoint` and `authenticationEndpoint` on another origin. Zero sink hits, no `outbound_*` event for `evil.test`. `authConfig.method=RSA_KEY` → `400 UNSUPPORTED_AUTH_METHOD`. An `http://` URL → `400 INVALID_REQUEST`.

Happy path:

- **AC-T2-03** `cg_student` opens "Seed activity". Within 10 s a new window reaches `{PUBLIC_APP_URL}/tool/launch?resource=seed&ltik=<value>`. `ltik` is 43 characters.
- **AC-T2-04** `GET /api/idtoken` (`LTIK-AUTH-V2 <cogniate key>:<ltik>`) → `200`: `user.id` = Moodle id of `cg_student`; `user.roles` has a Learner role; no `user.email`, no `user.name`; `platform.url` = `PUBLIC_MOODLE_URL`; `platform.clientId`, `platform.deploymentId` = `ltiSeed` values; `platform.productFamilyCode` = `moodle`; `launch.type` = `LtiResourceLinkRequest`; `launch.target` = `{PUBLIC_LTI_URL}/lti/launch/cogniate?resource=seed`; `launch.context.id` = course id of `COGNIATE-DEV-101`; `launch.resourceLink.id` not empty; `launch.presentation.documentTarget` = `document_target`; `services.deepLinking.available` = `false`. QA does not assert the other `platform.*` values.
- **AC-T2-05** `GET /api/idtoken?raw=true` → `200` with `iss`, `aud`, `sub`, `.../claim/message_type`, `.../claim/deployment_id`.
- **AC-T2-08** The `302` from `/lti/login/cogniate`: `Location` is Moodle `auth.php` with `scope=openid`, `response_type=id_token`, `response_mode=form_post`, `prompt=none`, `client_id`, `redirect_uri={PUBLIC_LTI_URL}/lti/launch/cogniate`, `login_hint` and `lti_message_hint` as sent, `state` and `nonce` of 43 characters (different in two launches). `Set-Cookie`: `__Host-` prefix, `Secure`, `HttpOnly`, `SameSite=None`, `Partitioned`, `Path=/`.
- **AC-T2-19** The `303` from `/lti/launch/cogniate` has `Referrer-Policy: no-referrer`, `Cache-Control: no-store`, and the state cookie with `Max-Age=0`. `GET /lti/launch/cogniate` → `405`.

Header and ltik errors:

- **AC-T2-06** On `/api/idtoken`: `qa-second` key + valid ltik → `401 INVALID_LTIK_AUTH_AUTHORIZATION_HEADER`; valid key + random 43-char ltik → `401 INVALID_LTIK_AUTH_AUTHORIZATION_HEADER`; `LTIK-AUTH-V2 <key>` without `:` → `401 INVALID_LTIK_AUTH_AUTHORIZATION_HEADER`; `Bearer <key>` → `401 INVALID_AUTHORIZATION_HEADER`; `SERVICE-AUTH-V1 …` → `401 INVALID_AUTHORIZATION_HEADER`. All bodies have the error shape.
- **AC-T2-07** `stack:restart -- lti-service --env LTIK_TTL_SECONDS=20`. A launch, then `/api/idtoken` less than 10 s after the redirect → `200`. The same call at TTL + 3 s → `401`. `stack:restart -- lti-service` restores the default.

Launch checks (security §2.2; QA captures the launch POST with Playwright and posts it itself; `qa-platform.test` lets QA sign its own tokens with a registered QA platform):

- **AC-T2-09** Replay of a used `id_token` + `state` from the same browser context → page `INVALID_STATE`, no redirect. Log `launch_check_failed {check: 1}`.
- **AC-T2-10** A captured form (not yet used by the browser) posted from a new browser context → page `STATE_COOKIE_MISSING` with the resource-link help text. No redirect. A second post of the same form with the cookie → `INVALID_STATE` (the state was used up).
- **AC-T2-11** Tampered payload (one character changed, same signature) → `INVALID_SIGNATURE`.
- **AC-T2-20** QA platform token with `alg=none`, and one with `HS256` (key = the JWKS `n`) → `INVALID_ID_TOKEN` (check 4).
- **AC-T2-21** QA platform token signed with a key whose `kid` is not in the QA JWKS → `INVALID_SIGNATURE` (check 6), and the log shows one JWKS refetch (`outbound_request` to `qa-platform.test`).
- **AC-T2-22** A real Moodle token held for 125 s, then posted with a fresh state and cookie of a new login (QA intercepts both) → `TOKEN_EXPIRED` (check 7).
- **AC-T2-23** The token of launch A with the state and cookie of launch B (same user, same platform) → `INVALID_NONCE` (check 8).
- **AC-T2-24** QA platform token with `aud` = another client id, and one with two `aud` values and no `azp` → `INVALID_ISSUER_OR_AUDIENCE` (check 5).
- **AC-T2-25** QA platform token with `version = 1.1` and one with `message_type = LtiSubmissionReviewRequest` → `UNSUPPORTED_MESSAGE_TYPE` (check 10).
- **AC-T2-26** QA platform resource-link token without `resource_link`, and one without `sub` → `MISSING_CLAIM` (check 11).
- **AC-T2-27** QA platform token whose `target_link_uri` differs from the login value → `INVALID_TARGET_LINK_URI` (check 12).
- **AC-T2-28** A POST to `/lti/launch/cogniate` with `error=access_denied` and a valid `state` (no `id_token`) → page `PLATFORM_ERROR` showing `access_denied`. The same state later → `INVALID_STATE`.
- **AC-T2-12** `POST /lti/login/cogniate` with `iss=https://evil.test` → `400` page `UNKNOWN_PLATFORM`, no `Location`. `POST /lti/login/unknown` → `404 UNKNOWN_TOOL_ACCOUNT`.
- **AC-T2-13** `target_link_uri=https://evil.test/x` at login → `400` page `INVALID_TARGET_LINK_URI`.
- **AC-T2-14** `PATCH /api/platforms/:id {deploymentIds:["999"]}` then a launch → `UNKNOWN_DEPLOYMENT`. Restore → launch works.
- **AC-T2-15** `PATCH … {active:false}` → launch shows `PLATFORM_NOT_ACTIVE`. `active:true` → works.

Logs and hooks:

- **AC-T2-16** After AC-T2-03 to AC-T2-28, `infra/.logs/lti-service.jsonl` contains none of the captured ltiks, `id_token`s, states or API keys.
- **AC-T2-30** Every error page shows a trace id that appears in a `launch_check_failed` or `login_rejected` event with the right `check` and `code`. Every JWKS fetch has one `outbound_request` event with `host` = the issuer host.
- **AC-T2-31** `npm run seed:lti-manual` twice gives the same `ltiSeed` values. After `stack:reset`, `stack:up`, `seed`, `seed:lti-manual`, a launch of "Seed activity" works again, and `seed.json` has the new ids. (Recreate after `DELETE /api/platforms/:id` is tested in T3c, AC-T3-19.)
- **AC-T2-17** (merged into AC-T2-29.)
