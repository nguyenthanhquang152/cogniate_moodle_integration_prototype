# T7: Full end-to-end in real Moodle

Owner: Author (harness and fixes). QA writes `tests/e2e/**`. Depends on: T1–T6 (QA may build an API-driven Scenario A after T5a and switch to the portal UI steps when T6 is done).

## Goal

One command proves the product goal on a clean, real Moodle 5.2: a Moodle admin connects the site, a teacher deep-links both courses, learners complete them, grades and completion appear in Moodle and in the portal.

## Scope (Author)

- `npm run e2e:reset`: `stack:reset`, `stack:up`, `seed`; wait until all `/healthz` answer and Moodle login works. Idempotent.
- `npm run test:e2e`: runs `tests/e2e` in the `e2e` container after `e2e:reset`, **without** the `acceptance` profile and without knobs. Artifacts to `tests/e2e/artifacts/` (git-ignored).
- `npm run demo:prepare`: drives Scenario A up to "the learner can open both activities" (by API and CLI), so a human demo starts in about 2 minutes. Prints the users and the activity URLs.
- `npm run moodle:cron` (fallback only; H13).
- Bug fixing is **time-boxed to one focused session**. A bug that needs more is reported to the Lead, who opens a new task per bug class.

## Files owned

Author: `infra/**`, root scripts, fixes. QA: `tests/e2e/**`.

## Scenario A — dynamic registration, both courses

1. Thanh (portal): Integrations → Moodle → Connect → `PUBLIC_MOODLE_URL`, "Dev Moodle", Automatic. Copy the URL.
2. Moodle `admin`: QA follows the steps that the wizard shows (`moodle-steps.json`): Manage tools, paste, "Add LTI Advantage", confirm page, "Connect", "Activate", edit "Tool configuration usage" and "Default launch container".
3. Thanh: upload the SCORM zip ("AI Website Sprint — SCORM") and the HTML zip ("AI Website Sprint — HTML"); publish both.
4. `cg_teacher`: `COGNIATE-DEV-101`, edit mode → Add an activity → "Cogniate (Thanh's Library)" → Select content → SCORM course → completion "Receive a grade" → Save. The same for the HTML course.
5. `cg_student`: SCORM activity (new window): menu page, lesson page ≥ 11 s, scroll to the end, correct option; wait for "Completed — score 100 sent to Moodle". The same in the HTML activity.
6. `cg_student2`: SCORM activity, wrong option, finish the pages.

## Scenario B — manual registration, second library, isolation

1. QA Library B (portal): Connect → `PUBLIC_MOODLE_URL`, "Dev Moodle B", Manual.
2. Moodle `admin`: "configure a tool manually" with the shown values (QA reads them by `key`, app contract §4.1), name "Cogniate (QA Library B)". Copy the six values back.
3. Library B: upload the HTML zip; publish it.
4. `cg_teacher` in `COGNIATE-DEV-102`: Add an activity → "Cogniate (QA Library B)" → Select content → add with completion "Receive a grade".
5. `cg_teacher` in `COGNIATE-DEV-101`: open "Select content" of "Cogniate (Thanh's Library)" again (do not save).
6. `cg_student`: complete the `COGNIATE-DEV-102` activity with the correct answer.

## Scenario C — security smoke in the real flow

1. Capture one learner launch POST (`id_token` + `state`) in Scenario A and post it again.
2. After A and B, grep all `infra/.logs/*.jsonl` for every captured ltik, service key, runtime token, `id_token` and API key.

## Acceptance criteria

- **AC-T7-01** `npm run test:e2e` runs Scenarios A, B, C from a clean reset with one command, exits 0, and takes ≤ 25 min with the images already pulled.
- **AC-T7-02** After A2: Moodle shows "Cogniate (Thanh's Library)" active, with "New window" and "Show in activity chooser". The connection is `registered`, then `connected` after A4.
- **AC-T7-03** After A4: the picker listed exactly Thanh's two courses. Both activities exist, each with a grade item of maximum 100. Both publications show "Linked".
- **AC-T7-04** Within 60 s of each completion (QA oracle polling, grader report screenshot): `cg_student` = 100.00 (SCORM) and 100.00 (HTML); `cg_student2` = 0.00 (SCORM) and no grade (HTML).
- **AC-T7-05** Completion: `cg_student` has both activities done ("Receive a grade"); `cg_student2` has the SCORM activity done and the HTML activity not done (QA oracle + course page screenshot).
- **AC-T7-06** Portal results: SCORM rows `cg_student` "Passed 100, Sent" and `cg_student2` "Failed 0, Sent"; HTML row `cg_student` "Passed 100, Sent". After "Refresh from Moodle": 100, 0, 100.
- **AC-T7-07** Every learner launch ends at `{PUBLIC_APP_URL}/play/...` in a new top-level window, and no final URL has `ltik`.
- **AC-T7-08** The picker in B4 lists only the library B course. The picker in B5 (opened after B3) does **not** list it.
- **AC-T7-09** `COGNIATE-DEV-102` gradebook: 100.00 for `cg_student`. Library B results show that row. Thanh's results views do not.
- **AC-T7-10** C1 gives `INVALID_STATE`. The C2 grep finds no captured secret.
- **AC-T7-11** Three consecutive runs pass with Playwright `retries: 0`.
- **AC-T7-12** Evidence in `docs/reviews/T7/qa.md`: screenshots (grader report, completion, portal results, Moodle tool settings), traces, run times.
- **AC-T7-13** At the start and the end of each run, every `/healthz` shows `"knobs": []` and `"profile": "default"`, and no `test_knob_active` event is in the run's logs.
- **AC-T7-14** Every Moodle label in `moodle-steps.json` that A2 uses exists on the live Moodle 5.2.4 page where the step says. QA lists any difference.
- **AC-T7-15** `npm run demo:prepare` on a fresh `e2e:reset` ends in ≤ 3 min; then `cg_student` can open both activities and reach the player.

## Known risks

- Moodle UI labels may differ from the steps. QA records each difference.
- After `e2e:reset` no Cogniate tool exists (`seed` does not run `seed:lti-manual`), so A2 should not show the choice page. If it does, QA follows the wizard step and chooses "register as new". B uses manual registration.
- Moodle may need `npm run moodle:cron` for some reports; qa.md says so.
- Chromium only. Teacher Deep Linking in Safari is not tested (Q16).
