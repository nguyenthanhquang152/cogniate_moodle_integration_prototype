## Goal

A Cogniate user connects a Canvas site or a Blackboard Learn site from the Integrations page, enters the operator's approval code, and gives the teacher the right next steps. Moodle flows stay the same.

## Scope

In:

- Integrations page: **Canvas** and **Blackboard** cards in the "LMS Publishing" filter, next to Moodle. No third-party logo file is added; the logo tile shows text initials ("Cv", "Bb"). Each card shows the status of the newest connection **of its own LMS** only.
- Routes: `/integrations/canvas/connect`, `/integrations/canvas/:connectionId`, `/integrations/blackboard/connect`, `/integrations/blackboard/:connectionId`. Form state is keyed by LMS and connection id (no data from the previous route).
- Canvas wizard and Blackboard wizard (4 steps each). Step texts are data files next to `moodle-steps.json` (`canvas-steps.json`, `blackboard-steps.json`); each step has `"verified": false` until a live check passes.
- Connection detail: LMS badge, site URL, Canvas service URL, deployment ids, Canvas "Add deployment ID" with an approval code, LMS-specific disconnect text.
- Capabilities: hide the web services section and the "Also create an empty Moodle course" option when the connection does not have them.
- Generic labels where the portal now serves several LMS types (list below). Texts that name Moodle for a specific connection use the connection LMS name. Simplified Technical English.
- Copy buttons show a selectable text box if clipboard access fails; a failed download never shows success.
- Site and service URLs are shown in the canonical form that the API returns.
- The `Approval code` field is a normal text input while the user types; the portal clears it after every submit (success or error) and never stores it in the URL, local storage or logs.

Out: any new API; Canvas Dynamic Registration; Canvas module items (`link_selection`); more than one page origin; editing an existing site or service URL; any provider endpoint input.

## Teacher steps (step 4 content)

- Canvas: Assignments, then `+ Assignment`; Submission Type `External Tool`; `Find`; `Cogniate`; select the course. Check that `Load This Tool In A New Tab` is selected (Cogniate asks Canvas for a new tab). Keep `Allowed Attempts` unlimited (Cogniate can send a better score later). Select `Save & Publish`. The assignment gets 100 points. Learners see it only when the course and the assignment are published.
- Blackboard Ultra: Course Content, then `+`, then Content Market, then `Cogniate`; select the course.
- Blackboard Original: a content area, then Build Content, then `Cogniate`; select the course.
- All: a learner must open the activity from the LMS. Learners are anonymous: Cogniate gets no names or emails.

These LMS labels are not verified on real tenants (M3 live matrix). The step data marks them `"verified": false`.

## Acceptance criteria

Evidence: browser tests by QA-E2E against the `acceptance` stack with `lms-sim` (`SIM`), 1440 px viewport, Chromium, as T6. Approval codes come from the AC-named `app:grant` command (M1).

- **AC-M2-01** The Integrations page with the filter "LMS Publishing" shows the Moodle, Canvas and Blackboard cards with the texts above. With connections of all three LMS types (also with equal names and times), each card shows only its own LMS's newest status. The Moodle card and its flow are unchanged (AC-T6 recipes pass with the label changes listed above).
- **AC-M2-02** With no `blackboard-sim` shared platform, the Blackboard card shows the not-ready text and a disabled `Connect`. After QA makes the shared platform and reloads, `Connect` works and step 2 shows `Client ID` = `qa-bb-app`.
- **AC-M2-03** Canvas step 1 lists the Canvas profile labels from `GET /app-api/lms-providers`, including `… (simulation)` in the `acceptance` profile. Each AC-M1-05 site input shows its rule text on the right field and no connection is made. A valid input makes one `pending` Canvas connection with the entered `siteUrl` and `serviceUrl` (empty service URL → equal to `siteUrl`).
- **AC-M2-04** Canvas step 2 shows the 4 rows of app contract §4.5 in order. `Copy JSON` puts exactly the body of `GET …/canvas-configuration` on the clipboard. `Download JSON` saves `cogniate-canvas-lti.json` with the same content. With the checkbox on, both use `?jwk=inline` (the JSON has `public_jwk` and no `public_jwk_url`) and the text shows the key id. With clipboard access denied, a selectable text box with the same JSON appears.
- **AC-M2-05** Canvas step 3 with valid values and a matching approval code → the connection is `registered` and step 4 shows the teacher steps. `GRANT_INVALID` (a used code), `GRANT_MISMATCH` (another deployment id; the field is marked), `PLATFORM_IN_USE`, `INVALID_PLATFORM_VALUES` (empty approval code) and `LTI_SERVICE_ERROR` (trace id) show the texts above; the connection stays `pending` in each error case. After every submit the `Approval code` field is empty, and the code is not in the page URL, local storage or session storage.
- **AC-M2-06** Blackboard steps 1 to 3 with a matching approval code → `registered`; step 4 shows the Ultra and Original steps. A deployment id that another library holds → the `DEPLOYMENT_IN_USE` text, and the connection stays `pending`. After an `LTI_SERVICE_ERROR` (QA uses the transport gate), a second `Save` with the same code → `registered`. A second deployment id on the same connection → the `DEPLOYMENT_FIXED` text. The wizard never shows a field for an issuer, an endpoint or a secret.
- **AC-M2-07** The connection list shows the LMS badge of each connection. A registered Canvas connection detail shows the site URL, the service URL and `Add deployment ID`; after a valid deployment id and `add_deployment` approval code the detail lists both deployment ids. Moodle and Blackboard details do not show it.
- **AC-M2-08** For Canvas and Blackboard connections the portal shows no web services section, and the publish dialog has no "Also create an empty Moodle course" option. For a Moodle connection with web services both still show (AC-T8 recipes). The `.mbz` section is labeled Moodle only.
- **AC-M2-09** Disconnect: the Blackboard dialog says `This switches off Cogniate for this Blackboard site only. Other schools are not affected. Cogniate items in Blackboard courses stop working, and connecting again later does not restore them.`; after confirm the connection is `disabled`. The Canvas dialog names Canvas. The Moodle dialog text is unchanged.
- **AC-M2-10** Publish dialog and results: the publish dialog title is `Publish to an LMS` and its `LMS connection` options show name, LMS and site host of every `registered` or `connected` connection (pending and disabled ones are not listed). Results of a Canvas publication show `Learner {sub} @ school-a.canvas.sim.test` and texts with "Canvas".
- **AC-M2-11** Keyboard only: a user can complete both wizards and the add-deployment form (Tab, Shift+Tab, Enter, Space; visible focus). Status changes are announced (`role="status"` or `aria-live`). axe-core finds no serious or critical issue on Canvas steps 1–3, Blackboard steps 1–3 and the Canvas connection detail.
- **AC-M2-12** Portal-only SIM scenario (with QA's simulator for the LMS side): make a Canvas connection (`canvas-sim-cloud`, `school-a`), register it with an approval code, publish the HTML course; the simulated teacher selects it; the simulated learner completes it; the Results page shows sync `sent`. The same for Blackboard (`blackboard-sim`, `learn-a`).
- **AC-M2-13** Routes: the four new routes open the right wizard or detail; `/integrations/blackboard/{id of a Canvas connection}` shows the portal "not found" view; switching from a Canvas detail to a Blackboard detail never shows the Canvas values on the Blackboard page; a library B session sees "not found" for a library A connection id.
