# M4: Guides, review pack and final conformance

Owners: Docs (Claude Code Opus 5.5, xhigh) and Architect (final conformance). Depends on: M3 results (Docs documents only behaviour that QA verified). Design: [ADR-011](../adr/ADR-011-multi-lms.md). Earlier docs spec: [T9](T9.md).

## Goal

The product team and a customer admin can set up Canvas or Blackboard from short guides. A reviewer sees in a few minutes what is proven, what is simulated and what is not tested.

## Scope

In:

- `canvas-admin.md`: developer key with our JSON (Paste JSON only), install by client id, the values and the approval request to the Cogniate operator, the Canvas URL (page host) and the Canvas service URL (account domain), Canvas environments, self-hosted Canvas (issuer must be the site host), the inline key snapshot and what to do after a Cogniate key change.
- `blackboard-admin.md`: register the tool with the Cogniate Application ID, the 9 values to check, user fields (role only), the deployment id and the approval request to the Cogniate operator, the warning about deleting a tool in Learn (F-BB-15), and what disconnect does to existing items.
- `operator.md`: (1) Blackboard: one Developer Portal application per LTI service host, the fields, the Deep Linking placement with Target Link URI `{PUBLIC_LTI_URL}/lti/launch/cogniate` and student access off, `lti:shared-platform`; (2) approval grants: the out-of-band check, `app:grant issue`, `revoke` and `list`, what goes in the note, recovery (revoke and issue again); (3) upgrade and rollback with `stack:data-backup` and `stack:data-restore`, with the lost-write warning (ADR-011 §14); (4) signing key rotation and inline Canvas keys.
- `teacher.md`: Canvas (graded assignment, new tab, Save & Publish) and Blackboard (Ultra and Original) sections.
- `troubleshooting.md`: `SERVICE_ORIGIN_MISMATCH` (page or service host), `DEPLOYMENT_NOT_ACTIVE`, `UNKNOWN_DEPLOYMENT` (a deployment without an approved binding, or a second Canvas install), `PLATFORM_IN_USE` (Canvas key reuse), `GRANT_INVALID`, `GRANT_MISMATCH`, `GRANT_IN_USE`, `DEPLOYMENT_IN_USE`, `PROVIDER_NOT_READY`, `INVALID_SITE_URL` rules, `ISSUER_RESERVED`, a blocked cookie in an LMS frame (browser, version and setting dependent).
- `README.md`: a supported-LMS table with the evidence label of each claim.
- `docs/human_review/`: one small interactive HTML page "Canvas and Blackboard at a glance": the tenancy diagram (ADR-011 §4), the operator approval grant (ADR-011 §4a) with its trust boundary, the profile table, the live matrix status, and the open decisions D-1 to D-11. It works offline.

Out: videos (not requested for this phase); any claim beyond the evidence.

## Acceptance criteria

- **AC-M4-01** Every new or changed guide step names its evidence label. A step from the live matrix that is still `UNVERIFIED` carries the note "Not yet tested on a real Canvas site" or "Not yet tested on a real Blackboard site". A `CANVAS-LOCAL` result is never described as hosted Canvas.
- **AC-M4-02** No document says "works with Canvas", "works with Blackboard", "certified" or an equivalent, unless the matching live rows are `PASS`. The README table says "signed simulation" for `SIM` evidence.
- **AC-M4-03** Simplified Technical English checks as in AC-T9-04: procedure sentences ≤ 20 words, descriptive sentences ≤ 25 words, paragraphs ≤ 6 sentences; measured with the T9 method, results in `docs/reviews/M4/docs.md`.
- **AC-M4-04** The guides contain no DataCamp value (client id, host, path) and no copied provider prose; provider facts link to the research file or to the provider page.
- **AC-M4-05** The review page opens from the file system without network access, shows the four items of the scope list, and states the three live blockers (B-1, B-2, B-3) in one sentence each.
- **AC-M4-06** The Architect conformance report compares the M1 and M2 code with ADR-011 and both contracts, lists every deviation with severity (charter §5), and gives APPROVE or CHANGES_REQUESTED. APPROVE needs no open BLOCKER or MAJOR deviation.
- **AC-M4-07** `docs/human_review/decisions-needed.md` (Lead) lists Q19 to Q22 of [open questions](../open-questions.md) and the follow-up decisions D-1 to D-11 with the defaults of ADR-011 §15.
