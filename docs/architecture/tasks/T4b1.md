# T4b1: Connections and publications (connect + publish)

Owner: Author. Depends on: T3b, T4a. Contract: [`../contracts/cogniate-app-api.md`](../contracts/cogniate-app-api.md) §4, §5 (without results), §6 rows `/tool/register`, §12. Security §2.5, §5, §6, §8. Flows §6a, §6e. Round 3: T4b is split into T4b1 (this file) and T4b2 (picker, launch handoff, tool page security).

## Goal

A Cogniate user connects a Moodle site (dynamic or manual registration) and publishes courses to it. A foreign "update existing tool" is refused before Moodle changes.

## Scope

In: connections API, publications API (without results), `GET` and `POST /tool/register` (confirm page, close page, `UPDATE_NOT_ALLOWED`, `REGISTRATION_FAILED` and `MOODLE_TOOL_MAY_EXIST` pages, error pages), codes `CONNECTION_NOT_PENDING` (409) and `LTI_SERVICE_ERROR` (502), page headers for these pages (security §5), the `Origin` rule (security §6), typed LTI service client with `X-Trace-Id`.

Out: picker, launch handoff, player shell (T4b2). Course shell (T8).

## Design notes

- Server-rendered pages with the portal CSS tokens. Escape all untrusted text.
- `connection.lti_platform_id` is unique: a platform belongs to one connection.

## Acceptance criteria

Setup: T4a state; both fixtures uploaded as Thanh's courses; one HTML course uploaded as library B's course.

- **AC-T4-07** `POST /app-api/connections {name:"Dev Moodle", siteUrl: PUBLIC_MOODLE_URL, method:"dynamic"}` → `201`, `status=pending`, `registrationUrl` matches `^{PUBLIC_LTI_URL}/lti/register/cogniate\?ref=[A-Za-z0-9_-]{43}$`.
- **AC-T4-08** Moodle `admin` pastes that URL → Add LTI Advantage. The frame shows the confirm page with `PUBLIC_MOODLE_URL`, the Moodle version, "Thanh's Library" and the privacy text. A real click on "Connect" works: the dialog closes by itself, Moodle lists a new Pending tool "Cogniate (Thanh's Library)", and the connection is `registered` with `platform.clientId` = its client id.
- **AC-T4-09** Opening the same URL again → `REF_INVALID`. A connection with `siteUrl https://other.test`, used from Moodle → `SITE_MISMATCH`. With `REF_TTL_SECONDS=20` (`stack:restart`), a URL used at TTL + 3 s → `REF_EXPIRED`.
- **AC-T4-10** Manual: library B makes a `method:"manual"` connection. `GET .../tool-configuration` returns exactly the 16 rows of app contract §4.1 (`key`, `label`, `value`) in that order. QA makes the manual tool "Cogniate (QA Library B)" in Moodle and saves it. `PUT .../platform` with the six values → `200`, `registered`. With `jwksUrl` on `https://evil.test` → `422 INVALID_PLATFORM_VALUES`.
- **AC-T4-30** Library B also tries dynamic registration with its own registration URL. Moodle shows the choice page. QA chooses "update" of Thanh's tool → the frame shows `UPDATE_NOT_ALLOWED` with "Go back in Moodle and choose Register as a new tool". Thanh's Moodle tool is unchanged (name, URLs) and Thanh's connection keeps its platform. QA repeats and chooses "register as new" → library B gets its own tool.
- **AC-T4-12** `POST /app-api/publications {connectionId, courseId:<SCORM course>}` → `201`, `available`. Again → `200`, same `id`. `withdraw`, then POST → `available`.
- **AC-T4-14** Publish to a `pending` connection → `409 CONNECTION_NOT_READY`.
- **AC-T4-33** Register page security: `GET /tool/register` has `frame-ancestors {PUBLIC_MOODLE_URL}`, `form-action 'self'`, `Referrer-Policy: same-origin`, `script-src 'nonce-…'`, no `X-Frame-Options`, no `Set-Cookie`. `POST /tool/register` with `Origin: https://evil.test`, `Origin: null`, and without `Origin` → `403`, `csrf_rejected` logged, connection still `pending`. A registration URL with an unknown `ref`, opened from Moodle, shows the `REF_INVALID` page **inside** Moodle's frame (error pages use `frame-ancestors https:`; the page has `data-error-code` and `data-trace-id`).
- **AC-T4-34** Tenant matrix: the library B session gets `404` for Thanh's connection (GET, `registration-url`, `tool-configuration`, `platform`, DELETE), publication (GET, withdraw, POST with Thanh's ids) and course version endpoints.
