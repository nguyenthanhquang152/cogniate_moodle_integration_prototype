# T8 (STRETCH): Native channel and course shell

Owner: Author. Depends on: T7 PASS. Start only if the Lead says so (Q12). Decision: [ADR-007](../adr/ADR-007-native-channel-stretch.md). Contract: app contract §11. Spike facts: `infra/moodle/SPIKE-NOTES.md` §8.

## Goal

Show that a Cogniate SCORM course version can reach MoodleCloud as a native course (a `.mbz` built by a real Moodle and restored by the admin), and that the app can make an empty Moodle course with web services.

## Scope

In:

- Build Runner: a script that starts a separate compose project (`cogniate-build-<id>`) with `erseco/alpine-moodle:v5.2.4` and its own Postgres, on an **internal** network (no internet, no link to the main stack). It copies the zip in read-only, makes a hidden course `cogniate:{courseId}:{variant}:{lang}` with one SCORM activity (grade method "highest", completion "Receive a grade"), runs `backup.php --nousers`, copies the `.mbz` out, and removes the project and its volumes.
- Knobs `BUILD_RUNNER_HOLD` and `BUILD_RUNNER_FAIL_AT` (H12, tasks README §3).
- `POST /app-api/courses/:courseId/versions/:versionId/mbz` (`202`), `GET .../mbz` (status), `GET .../download?kind=mbz`.
- Portal: "Build Moodle backup (.mbz)" with status, download and MoodleCloud restore steps.
- Course shell: `PUT /app-api/connections/:id/web-services`, `createMoodleCourse` on publish, publish dialog checkbox "Also create an empty Moodle course" (only with a token), link to the Moodle course.

Out: HTML courses, LTI activities inside the `.mbz`, automatic restore.

## Acceptance criteria

- **AC-T8-02** `POST .../mbz` → `202`. Within 5 min (images pulled), `GET .../mbz` → `status=ready`. The download is a file > 12 MB.
- **AC-T8-03** With `BUILD_RUNNER_HOLD=1`: `docker network inspect` of the build network shows `Internal: true` and no other network on its containers; DNS for `moodle.test` fails inside. After the hold is released and the build ends, `docker ps -a` and `docker volume ls` show no `cogniate-build-*` items.
- **AC-T8-04** The `.mbz` (tar.gz) has `moodle_backup.xml` with a Moodle release of `5.2`, `users` = 0, and exactly one activity of module `scorm`. Other modules that Moodle adds by default (for example the Announcements forum) are allowed.
- **AC-T8-05** `admin/cli/restore_backup.php --file=<mbz> --categoryid=1` in the test Moodle makes a hidden course with idnumber `cogniate:{courseId}:default:en` and one SCORM activity.
- **AC-T8-06** QA makes the course visible (QA oracle `core_course_update_courses`) and enrols `cg_student` (product WS). `cg_student` completes the SCORM activity in Moodle's own player with the correct answer. The Moodle gradebook shows 100.00, and the SCORM report shows "Passed".
- **AC-T8-07** With `BUILD_RUNNER_FAIL_AT=backup`: the portal shows the build as failed with the reason, and no `cogniate-build-*` container or volume remains.
- **AC-T8-08** (was AC-T4-11) `PUT .../web-services {token:<product WS token>}` → `200` with `release` starting `5.2` and the function list. A wrong token → `422 WS_TOKEN_INVALID`.
- **AC-T8-09** (was AC-T4-13) Publish with `createMoodleCourse:{}`: Moodle has one course with `idnumber cogniate:<courseId>:default:en`, `visible=0`. A second publish → `shellStatus=exists`, still one course.
- **AC-T8-10** (was part of AC-T6-07) With a token, the publish dialog shows the checkbox; after publish it shows a link to the new Moodle course. Without a token there is no checkbox.
