# T9: Docs and human review pack

Owner: Docs role (`README.md`, `docs/guides/**`, `docs/human_review/**`). Depends on: T7 PASS. Rule: document only behaviour that QA verified (charter §1).

## Goal

The Vietnamese product team can run, understand and judge the prototype without the agents, with little reading (Karpathy principles, inputs §7).

## Scope

- Root `README.md`: what it is, the one-page "start here", links.
- `docs/guides/`: run the stack (`npm run demo`, `npm run demo:browser`, `npm run demo:prepare`), Moodle admin guide (connect, activate, edit), teacher guide (add Cogniate content with the Moodle 5.2.4 path Edit mode → "Add content" → "Activity or resource" → "Cogniate (<library>)" → "Add" → "Select content", then completion "Completion conditions" → "Add requirements" → "Receive a grade"; Q-T7-02), learner view, troubleshooting.
- `docs/human_review/`: proven / not proven (from the architecture README §6 and the qa.md files), decisions needed (open questions), deferred findings, one diagram per flow.

## Acceptance criteria

- **AC-T9-01** (human check) A person who did not build the stack follows the root README and `docs/guides/` on macOS, with the images already pulled, and reaches the Moodle login page and the portal sign-in page in their browser in ≤ 10 minutes. The Lead names the person (or accepts a QA run). QA can time the command part in a fresh clone and check the two pages with Playwright and `--host-resolver-rules`; the qa.md row says which part a human did and lists the steps that were unclear.
- **AC-T9-02** Every behaviour that the guides describe has a QA-verified AC id next to it (or a link to the qa.md row).
- **AC-T9-03** The human review pack lists every "Not proven" item of the architecture README §6 and every open question with its recommendation.
- **AC-T9-04** STE check: sentences in procedures ≤ 20 words, descriptive sentences ≤ 25 words, NOTE / WARNING / CAUTION used as in inputs §7. Reviewer-B confirms.
