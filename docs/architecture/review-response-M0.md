| B-M0-03 | MAJOR | Done. Two-phase redemption with an attempt id: phase 2 activates only if the same attempt still holds the grant, the grant is not revoked or replaced, and the connection is still in its start state; otherwise the attempt compensates (switches off only what it created, never a record owned by an active connection) and answers with a defined code. Revoke and replacement are allowed during a redemption and cancel it. Only the owning attempt clears the attempt fields, so a stale attempt cannot disturb a newer one. Expiry is checked at phase 1 only. **Fence (Lead `msg_8f89cbe8d700`):** every record that an attempt creates, reactivates or takes over carries the attempt id as binding ref; every app switch-off, delete or take-over is a compare-and-set on a ref of the same connection, done by the LTI service in one transaction (`ifBindingRef`, `409 BINDING_REF_MISMATCH`); so a stale compensation, disconnect or suspend cannot switch off a newer binding, and `release` waits until every attempt lease has ended. A failed compensation is logged and repaired with `app:binding suspend`. Files: ADR-011 §4a, R-M-15; LTI contract §9.4–§9.6, §9.15, D20; app contract §4.4, §4.7.1 (outcome table), §4.7.2, §4.8, §4.9; data model §4.1, §4.2 (`redeeming_attempt`, `binding_attempt`, binding refs); security §12.
